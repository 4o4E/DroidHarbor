
# 手机设备池需求与选型

## 一、目标与现状

需要长期托管 Android 手机，让不同机器上的 AI 可以远程使用手机。当前手机通过 USB 连接生产 WinServer，已有 ADB；新平台同时支持 USB 与 Wi-Fi ADB 接入。预计先接入约 3 台，未来最多约 10 台。

用户希望从不同设备的浏览器查看手机画面，操作逻辑与 scrcpy 保持一致，人工入口统一网页，不保留 eScrcpy 产品入口或共存兼容要求。用户已使用 WebAppFlaskscrcpy 并确认不适用，决定独立重写，只参考功能逻辑、不复制应用代码。开发目标、技术选型与接口边界见[项目规划](../docs/项目规划.md)。

## 二、核心需求

### 1. 设备连接与长期托管

- 手机可以通过 USB 或 Wi-Fi ADB 接入宿主机，由平台统一管理；两条接入链路都属于首版范围。
- 支持掉线、未授权、无线配对失效和重新连接等状态；同一手机同时存在 USB/Wi-Fi 连接时不得重复分配。
- ADB 和设备池由服务器长期运行并恢复已登记连接；手机首次授权及必要配对由管理员完成。调用方通过平台 Skill 建立租约 ADB 连接，无需用户逐任务操作。
- 希望部署简单、资源占用和维护成本与最多约 10 台手机的规模相匹配。
- 首版服务端支持 Windows 原生与 Linux Docker，使用 SQLite；Linux 通过 Compose 分别部署平台和 ADB。仅内网/VPN 访问，两种部署均需覆盖 USB/Wi-Fi、持久化及重启恢复。
- 平台由一个 Go 服务统一提供网页静态文件、API、租约网关和投屏；管理员使用访问令牌登录，不建立账号密码体系。AI 仍使用可撤销调用凭证与任务独立授权。

### 2. AI 设备池与租约

- 不同 AI 任务需要共享手机池；同一台手机同一时间最多由一个 AI 任务认领。
- 初次认领与每次显式续租均授予未来 15 分钟；续租次数和任务累计运行时长不限，任务正常结束后主动释放。
- 到期后旧任务不能继续通过平台入口发起操作；服务重启使全部旧租约失效。不能只靠 Skill 提示 AI 遵守，服务端必须撤销旧连接与重连权限。
- 离线、未授权或上一任务的平台资源尚未回收时不得重新分配；平台资源回收且连接健康后可回池，不要求终止手机用户应用或任意后台程序。
- 用户不手动给每个任务分配手机：手机配置能够反映业务用途和账号环境的标签，任务声明需要的标签，由设备池自动选择匹配且空闲的手机并认领。
- 部分手机已登录电商平台账号，用于查询对应平台的商品；任务必须分配到有对应账号环境的手机，不能因为其他手机空闲而误分配。标签描述用途，不记录账号密码等敏感信息。
- 没有匹配且可用的手机时，不得改用不匹配设备；应向任务明确返回不可用。是否等待及等待多久由任务调用方决定。
- 已确认保留应用状态，只回收平台拥有的连接、转发和会话等资源，不清应用/账号数据、不主动停止用户后台程序。允许后台程序继续运行及产生副作用，不宣称设备执行环境隔离；平台资源清理失败仍须隔离。

### 3. 浏览器查看与人工接管

- 网页按 scrcpy 的直接操作语义提供实时画面、点击、长按、滑动、鼠标键映射、键盘、剪贴板和文件拖入；浏览器限制导致的差异必须明确，不用另一套操作逻辑代替。
- 首版正式支持桌面 Chrome/Edge（Windows/Linux）与 Android Chrome；Safari/Firefox 不纳入首版正式兼容承诺。
- 用户保留人工接管能力；AI 持有租约不应妨碍用户接管，也不应自动改变 AI 的租约。
- 人工与 AI 同时操作可能互相干扰；当前不自动暂停 AI，是否增加独占人工接管属于单独的业务决策。
- 网页投屏分辨率、帧率上限、编码目标码率独立调整，保持手机画面比例；默认长边上限 1920、30 fps、4 Mbps，不降低原生 ADB 截图分辨率。
- 同设备所有网页观看者共享采集与画质配置，调整影响这些观看者但不改变 AI 租约；生效参数和切换状态明确，不通过拉伸/裁切满足显示尺寸。
- 设备池卡片整体点击进入工作台，独立管理入口不同时导航。工作台左侧显示带预览的设备列表，点击直接切换；释放本窗口的旧输入与观看，不影响其他窗口或 AI 租约，保留只读意图。
- 设备池及工作台左侧列表显示共享低频截图预览，默认每 5 秒更新可见设备；后台/不可见时停止对应请求，服务端按需生成小图并复用有界缓存，显示真实拍摄时间，离线或失败不把旧图当实时画面。
- 独立小窗仅显示一台手机画面和底部一排必要按钮，不增加设备信息、选择器或可展开面板。关闭主页面不影响已打开小窗；所有窗口受管理员授权约束。不接入 Document PiP，不增加系统级置顶。
- 小窗只用浏览器 popup，允许用户移动和手动缩放，底部提供一键调整窗口尺寸；画面等比适配，不改变编码参数。浏览器拒绝尺寸请求时明确反馈，不用 CSS 缩放冒充窗口变化；不增加桌面客户端或锁定外框。
- 首版不含音频、录屏、群控、应用仓库、MCP 和完整权限管理后台；包含截图、剪贴板、APK 安装及文件传输。无需 eScrcpy 共存验收，不擅自卸载现有软件。

### 4. AI 调用方式

- 平台随版本交付供调用方 AI 使用的 Skill，组织按标签认领、获取连接、续期、原生 ADB 操作和释放；它不是用于开发网页的 frontend-library skill。
- Skill 是使用入口，不是租约强制边界。服务端必须把 ADB transport、内部子流和重连绑定到任务租约，并在过期或撤销时阻断。
- 已确认 Skill 调用按任务启动的辅助 CLI：CLI 建立认证加密通道，配置任务专用本地 ADB Server 和设备入口，调用方继续使用原生 adb 完成 shell/exec-out、截图、点击、滑动、输入和文件传输。管理 API 负责租约，不重复建设纯 HTTP AI 操作接口。
- 调用方支持 Windows 和 Linux，不限制 harness。Skill 与 CLI 使用通用命令、退出码和机器可读结果，不要求安装特定 harness 插件或接入其结束钩子。
- 手机到平台的无线 ADB 与调用方到平台的远程 ADB 均需支持，但两者独立；USB 手机也能经平台远程使用。调用方不直连手机原始无线端口，也不取得无约束的服务端 ADB Server。
- Appium、uiautomator2 只预留连接、能力声明、端口映射及设备端服务生命周期的扩展合同；当前不实现、部署或承诺兼容。
- CLI 不做全局常驻服务、不后台自动升级、不自动换设备或重放操作，只清理本任务资源。服务端撤销不依赖 CLI 配合；随机端口不是身份，同系统权限下的恶意任务隔离需要调用方运行环境支持。
- 已确认显式续租：每次由调用方主动执行 CLI 命令，将有效期更新为服务端当前时间起 15 分钟，不叠加囤积时间、不限续租次数或累计占用时长。CLI 不自行续租，连接保活和 ADB 流量不延长授权；长操作期间也需显式续租。

## 三、选型过程

### 1. 共享 ADB Server

让手机通过 USB 连接一台服务器，其他机器通过网络访问其 ADB Server。ADB 原生支持在多设备中按序列号选择手机，且不要求手机开启无线 ADB。

**结论：适合作为底层设备连接方式，但单独使用不满足需求。** ADB 不提供 AI 任务级认领、续期和释放；多个调用方也可能同时操作一台手机。

### 2. DeviceFarmer STF

[DeviceFarmer STF](https://github.com/DeviceFarmer/stf) 是较完整的开源设备农场，提供设备列表、浏览器控制、认领与释放 API，以及 Linux USB + Docker Compose 部署。

评估中发现：

- 当前官方 Compose 定义 17 个服务，其中 16 个长期运行，`migrate` 是一次性迁移任务；多个 STF 角色可复用同一镜像。
- 现成能力较多，但设备池之外还包含多进程消息系统、数据库和网页管理等；对最多约 10 台设备，部署与维护复杂度是否值得需要权衡。
- STF 的 API 文档有认领时超时参数，但这不足以证明它满足 AI 任务续期、旧任务连接失效及强制回收的要求。
- 理论上已有 ADB Server 或 RethinkDB 时可复用对应能力，但其他服务的可裁剪范围没有完成验证，不能假定删掉某个容器仍能保持全部功能。

**结论：功能完整，但整体偏重，不采用其作为本项目底座。** 没有进行同环境资源实测，不能给出它与其他方案的确定占用差异。

### 3. 从零自建设备池

复用现成 ADB、scrcpy-server 与成熟媒体/前端组件，独立实现 USB/Wi-Fi 设备发现、任务租约、租约 ADB 网关、配套操作 Skill 和浏览器工作台。

**结论：已确定独立建设，后端及调用方辅助 CLI 使用 Go，浏览器投屏使用 Pion WebRTC，存储使用 SQLite。** 主要工作在任务租约、标签原子认领、旧 ADB 连接撤销、平台资源回收、scrcpy 网页交互及长期运行。用户已授权实施并明确批准工程设计中的 SQLite schema。

### 4. WebAppFlaskscrcpy

[WebAppFlaskscrcpy](https://github.com/zhoujun94511/WebAppFlaskscrcpy) 提供 Flask、Vue、SQLite、scrcpy 和 WebRTC 组成的浏览器设备平台，包含设备占用、投屏与控制等功能。

用户已实际使用并认为不满足需求，明确不采用其作为底座、不再安排参考项目试用。新平台只参考设备管理、投屏和操作流程，不复制其 Python/Vue 实现，也不兼容其数据库或接口格式。

其用户级占用不能直接当作本项目所需的任务级隔离，设备直接选择不能替代按账号环境标签自动认领。新项目按独立合同实现租约网关和平台资源回收；不将关闭连接宣称为手机后台程序已停止。

性能问题是用户报告的重写原因之一。公开源码的视频主链路使用 H.264 直通，不能未经测量就将全部瓶颈归为 Python 转码；新项目应避免无用编解码并验收真实资源与延迟。

### 5. ws-scrcpy 与 Android Device Lab

- [ws-scrcpy](https://github.com/NetrisTV/ws-scrcpy)：提供基于 scrcpy 的浏览器投屏和控制；项目说明未证明提供所需的 AI 任务级租约。若选用，设备池和租约仍需另行实现。
- [Android Device Lab](https://github.com/asafasa2/android-device-lab)：提供设备预约、网页和 API，架构较轻；其画面是连续截图而非 scrcpy 视频流，公开的远程 ADB 能绕过预约。项目规模较小，不作为当前首选。

## 四、新平台部署方向

首版正式支持 Windows 原生与 Linux Docker，均使用 SQLite，仅内网/VPN 访问。Windows 使用宿主 ADB；Linux 用 Compose 分别部署平台与 ADB，ADB 容器负责 USB/Wi-Fi 接入，平台经受控内部连接访问它。平台容器更新不要求重启 ADB。

Linux 需验收 USB 权限/热插拔、无线配对、两容器连接、分别持久化的业务数据和 ADB 授权材料、自启动与媒体网络。一个 USB 设备只能由一个服务端 ADB 实例接入；任务回收只清理归属资源，不用重启 ADB 或删除全部转发代替定向清理。

调用方只使用绑定任务租约的 ADB 入口，手机原始无线端口和服务端管理端口不作为旁路。平台服务或平台容器重启使旧租约全部失效，回收并确认连接健康后再分配；单独 ADB 重启视为连接中断，不隐式续租或重放动作。两种部署不扩大为多宿主统一调度。

## 五、新平台验收与后续决策

1. **设备接入**：USB 与 Wi-Fi 手机均可被登记和使用；无线断连、配对失效正确反馈；同机双链路不重复分配。
2. **网页操作**：按 scrcpy 语义验证触控、鼠标、键盘、剪贴板和文件传输；验证三项画质独立调整、保持比例及同设备共享配置，不含音频/录屏。
3. **租约与标签**：并发认领只有一个成功；绝不选错账号环境；共用调用身份的不同任务保持隔离。
4. **远程 ADB**：Skill 和任务级 CLI 建立认证通道，原生 adb 连接本地入口并操作远程手机；租约失效后旧连接、子流和重连均不能继续操作；AI 结束后不能仅因 CLI 存活而无限续租。
5. **回收**：旧访问与平台资源清理成功、连接健康后回池；用户应用、账号和后台状态保留。平台资源回收失败须隔离，但不因存在用户后台程序而要求人工确认。
6. **人工入口**：统一网页授权会话，人工操作不自动释放或暂停 AI；不要求 eScrcpy 共存兼容。
7. **运行能力**：分别验证 Windows 原生和 Linux 双容器、自启动、持久化及重启恢复；资源/延迟/建流/稳定性先测量再定数值门槛，不以选型代替性能证明。
8. **调用方兼容**：Windows/Linux 均完成通用 CLI 使用与资源清理验收，不依赖 harness 专用插件或结束通知。
9. **兼容边界**：Appium/uiautomator2 仅保留扩展合同；不列为当前功能验收项。

首版业务与架构边界均已确认，详见[项目规划](../docs/项目规划.md)。[OpenSpec 首版提案](../openspec/changes/build-droidharbor-v1/proposal.md)及[工程设计](../openspec/changes/build-droidharbor-v1/design.md)是实施合同，用户已批准工程开发和数据库 schema。UI 实际布局另行评审；用户稍后提供测试机，性能门槛在真机测量后确定，不以非真机测试替代。
