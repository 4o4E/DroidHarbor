# Proposal

## Why

现有方案不能满足按账号环境分配真机、任务级原生 ADB 授权和可维护的网页控制需求，用户已决定独立重写。DroidHarbor 首版要为约 3–10 台 Android 手机建立完整的“领用—连接—操作—显式续租—释放”闭环，并提供统一网页人工入口，而不是只交付投屏界面或后端骨架。

## What Changes

- 新增 USB/Wi-Fi ADB 设备登记、授权/配对、稳定设备身份、双链路去重、标签匹配和维护状态。
- 新增任务级原子认领；认领及每次显式续租有效 15 分钟，不限制续租次数或累计任务时长。到期、撤销及平台重启使旧授权失效。
- 新增服务端强制执行的租约 ADB 网关，覆盖已建立 transport、shell/sync 子流、待派发数据和重连；不开放原始服务端 ADB 管理端口。
- 交付 Windows/Linux Go CLI 及产品操作 Skill。每任务独立本地 ADB 实例、配置和入口，不依赖 harness 插件，不自动续租、换设备或重放操作。
- 新增网页设备池、管理与工作台：整张设备卡片点击进入，工作台左侧带预览列表直接切换设备；scrcpy 式触控/鼠标/键盘、多指模拟、中文/剪贴板、截图、APK 安装、文件传输及只读会话。人工操作不自动改变 AI 租约。
- 设备池及工作台左侧列表采用共享低频截图预览，默认每 5 秒更新可见设备；服务端按需生成小图并复用缓存，不维持列表视频流、不改变工作台画质及原始截图，不将旧帧标作实时画面。
- 独立浏览器 popup 仅显示指定手机与底部一排按钮，关闭主页面仍有效；允许用户移动和缩放，提供一键调整窗口尺寸，画面保持比例且不修改编码参数。浏览器限制如实反馈，不增加桌面客户端。
- 新增手机 H.264 编码、Pion WebRTC 转发和浏览器解码链路，每设备共享一份采集。分辨率、帧率上限、目标码率独立调整并保持画面比例；默认长边 1920、30 fps、4 Mbps，修改影响同设备全部网页观看者。
- 回收仅撤销访问并清理平台拥有的资源，保留手机应用、账号、业务文件及后台状态；清理失败隔离，连接健康且清理完成后回池，不保证设备副作用清零。
- 提供 Windows 原生和 Linux Docker Compose 双容器部署；后者分别运行平台与 ADB。SQLite 持久化业务元数据，内网/VPN 使用，正式支持桌面 Chrome/Edge 与 Android Chrome。
- 提供管理员访问令牌登录、可撤销调用凭证、能力发现、版本合同、状态事件、运行记录及备份恢复；静态前端、API、网关与投屏由单 Go 服务统一提供。性能先测量，再由用户确认数值验收门槛。
- 补充 Windows 前台试用发布：服务端和客户端按角色独立打包。服务端将网页与锁定 scrcpy-server 内嵌到 EXE，点击后零参数读取 `.env`，提供直接可用的模板、启动自动初始化、首次管理员 token 的控制台/日志交付、轮转日志及故障诊断；媒体默认 WebRTC 自动地址协商，无需填写 IP，特殊网络保留显式覆盖。客户端提供任务 CLI、产品 Skill 和操作说明。应用提供 HTTP/WS，移除内置 TLS、证书及固定 origin 要求，ADB 由外部提供。

**明确不做**：音频、录屏、群控、应用仓库、MCP、多语言 SDK、完整权限管理后台、SSO、多宿主调度、集群高可用、公网直连、eScrcpy 入口及共存兼容、Document PiP 或小窗强制置顶。Appium/uiautomator2 只保留连接、能力及生命周期扩展合同，不部署、不实现、不宣称兼容。

本变更是首版整体交付的规划单元，内部按可运行纵向阶段实施，不能把阶段性骨架当作首版完成。项目无既有业务接口或数据，因此不存在向参考项目迁移或保留旧接口的要求。

## Capabilities

### New Capabilities

- `device-pool`：设备登记、USB/Wi-Fi 接入、稳定身份、标签、连接状态与分配资格。
- `task-leases`：原子认领、任务授权、固定租期、显式续租、撤销、回收与重启失效。
- `remote-adb`：原生 ADB 连接、服务协商、二进制桥接、子流撤销及未来工具边界。
- `caller-skill`：harness 无关的 Skill/CLI 使用流程、本地任务环境、错误与退出清理。
- `web-workbench`：网页人工控制、工作台设备切换、独立小页面、共享低频预览、只读权限、媒体共享、可调画质、文件与截图交互。
- `access-control`：管理员及调用方认证、凭证撤销、任务凭证隔离和数据可见范围。
- `platform-operations`：双部署、持久化、服务恢复、版本发布、健康检查、备份和测量交付。

### Modified Capabilities

无。当前 `openspec/specs/` 尚无正式能力规格，以上均为新增能力。

## Impact

- 依据：[项目规划](../../../docs/项目规划.md)、[原始需求](../../../ref/需求&选型.md)及本变更的设计、规格与任务清单。
- 本变更从仅有规划和工具的仓库开始实施，没有既有业务接口或数据迁移负担。
- 实现涉及 Go 服务与 CLI、React/TypeScript 前端、SQLite schema/迁移、API 合同、设备协议适配、产品 Skill、Windows 服务配置、Linux 镜像/Compose 及验收文档。
- 用户已批准工程实施及 `design.md` 第 9 节数据库 schema；后续架构或 schema 调整仍须确认。
- 依赖官方 platform-tools、锁定版本的 scrcpy-server、Pion 和 frontend-library 指定组件；具体版本及兼容矩阵以获取和运行证据为准。
- UI 实际布局须评审后进入正式页面实现。用户稍后提供测试机，不操作非指定设备，不以规划、编译或模拟数据代替产品验收。
