# Spec Delta

## Purpose

让远程调用方在任务租约约束下使用真实原生 adb 操作手机，同时保留 shell 和文件协议的可观察语义，约束连接复用、子流和重新连接，避免将平台设备池退化为不受任务授权控制的 ADB 管理服务器。

## ADDED Requirements

### Requirement: 原生 ADB 任务连接
平台 SHALL 提供经认证加密通道访问的任务级设备入口，使原生 adb 可以通过调用方 loopback 入口连接已认领手机。该入口 MUST 只对应当前租约设备，不暴露服务端 ADB 管理地址或其他真实手机。

#### Scenario: 使用 USB 手机远程操作
- **WHEN** 任务认领一台仅通过 USB 接入平台的手机并建立认证连接
- **THEN** 原生 adb 可以连接任务本地入口并操作该手机，无需调用方直连手机无线端口

#### Scenario: 查询本任务连接设备
- **WHEN** 调用方通过任务专用本地 ADB 查询设备列表
- **THEN** 平台入口只代表本租约设备，不提供切换到其他平台手机的通道

### Requirement: 命令与能力合同真实
平台 SHALL 发布 API/网关协议及支持服务能力，首版支持经协商的 shell、exec-out、文件 sync 和必要设备信息。平台 MUST NOT 宣称所有原生 adb 服务或目标设备全部 features 均已支持。

#### Scenario: shell 与二进制截图
- **WHEN** 调用方在兼容设备上执行 shell 命令与 `exec-out screencap -p`
- **THEN** 返回真实 shell 输出及协商的退出状态，截图保留原始二进制内容，不使用网页压缩帧替代

#### Scenario: 文件往返
- **WHEN** 调用方通过原生 push/pull 传输包含任意二进制内容的文件
- **THEN** 成功结果对应真实文件内容，设备拒绝或中断时保留错误，不把开始传输当作完成

#### Scenario: 请求未声明的设备服务
- **WHEN** 调用方请求未支持的转发、reverse、设备重配置或其他服务
- **THEN** 对应端到端服务访问被拒绝且能力中不宣称支持；本地 adb 创建监听成功不等于平台已支持目标服务

### Requirement: 任务与占用代次强绑定
平台连接和所有子流 MUST 绑定任务凭证、租约、设备占用代次及当前平台运行代次。仅知道 taskId、网关地址或真实手机地址 MUST NOT 通过平台认证。首版将共享调用机视为可信环境；本地原生 ADB Server 不认证发起命令的任务，产品 MUST NOT 将其本地端口宣称为任务安全隔离边界。

#### Scenario: 使用其他任务凭证
- **WHEN** 同一调用账号下的任务 B 持自己的凭证访问任务 A 的连接
- **THEN** 平台拒绝，不因共享调用账号而允许控制 A 的设备

#### Scenario: 旧材料直接连接新任务网关
- **WHEN** 旧任务保留地址、ADB 密钥和连接记录，在入口复用后使用旧材料建立到新任务网关的连接
- **THEN** 平台拒绝旧凭证和旧密钥，不能获得新的设备租约

#### Scenario: 原生客户端先尝试默认用户密钥
- **WHEN** 原生 ADB Server 先提交未登记的默认密钥签名，随后提交有效任务密钥签名
- **THEN** 网关在有界的标准 AUTH 协商内只接受任务密钥；超限、超时、未知公钥或始终无有效签名时拒绝，不允许未认证数据到达设备

#### Scenario: 可信调用机复用本地 ADB Server 端口
- **WHEN** 旧原生 adb 命令指向被新任务本地 Server 复用的地址
- **THEN** 产品明确该本地客户端访问不在任务隔离保证内，不声称任务密钥能阻止其使用新 Server 已获授权的连接；不互信任务需要调用方提供独立网络环境

### Requirement: 连接全过程执行撤销
平台 MUST 在建连、打开子流和数据派发时执行租约约束，终止时打断既有交互 shell、文件子流与阻塞传输，拒绝新服务和重连；不能只在第一次握手鉴权。

#### Scenario: shell 建立后租约过期
- **WHEN** 任务先打开长时间交互 shell，再等到租约过期后继续输入
- **THEN** 既有连接失效，后续输入不能经平台派发，不能借长连接绕过过期

#### Scenario: 文件传输期间撤销
- **WHEN** 管理员撤销正在传输文件的任务授权
- **THEN** 传输及关联子流终止，排队但未派发的数据不继续发送；已经写入手机的部分不被伪报回滚

### Requirement: 二进制流与背压
网关 SHALL 保留协议二进制语义并实施有界背压；错误包、超出协商范围的数据或无效子流状态 MUST 明确关闭受影响连接，不得无限缓存或影响其他设备会话。

#### Scenario: 慢接收端
- **WHEN** 一个调用方停止读取文件数据或持续发送超过可处理速率的数据
- **THEN** 该通道受到背压或明确终止，不无限占用内存，也不阻止其他任务续租和撤销

#### Scenario: 非法协议输入
- **WHEN** 连接发送无效长度或不符合协商状态的协议包
- **THEN** 平台拒绝该连接，不把异常数据当作设备命令继续转发

### Requirement: 不重放未知结果
连接中断或超时后平台 SHALL 区分已知失败与结果未知，不自动重放设备动作、重新认领或更换设备。取消访问不等于撤销手机已收到的动作。

#### Scenario: 操作响应丢失
- **WHEN** 点击或发消息命令可能已经到达 Android，但连接在返回结果前中断
- **THEN** 调用方得到中断或结果未知，不出现平台自动重复点击或发消息

### Requirement: 扩展工具不得获得旁路
平台 SHALL 保留稳定设备身份、租约连接描述、能力版本和资源生命周期合同供未来工具使用；首版 MUST NOT 运行或宣称兼容 Appium/uiautomator2，不暴露无租约端口作为替代入口。

#### Scenario: 客户端检查自动化工具能力
- **WHEN** 调用方查询首版是否支持 Appium 或 uiautomator2
- **THEN** 能力响应不宣称已支持，平台不自动安装或启动相关手机 agent，也不返回绕过租约的原始 ADB 入口
