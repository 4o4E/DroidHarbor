# Spec Delta

## Purpose

为不同 harness 中运行的 AI 提供统一且可执行的设备池使用说明与辅助 CLI，使 Windows 和 Linux 调用方完成认领、连接、原生操作、续租和释放，并正确处理任务异常而不依赖特定运行器的内部生命周期协议。

## ADDED Requirements

### Requirement: 随产品交付完整调用流程
平台 SHALL 随版本交付含产品 Skill 及 Windows/Linux amd64 CLI 的客户端 Skill ZIP，覆盖能力检查、最小设备列表、按标签或精确名称/ID 认领、连接、原生操作、显式续租、查询和释放；产品 Skill MUST 与项目开发 skills 区分。

#### Scenario: 新调用方完整使用
- **WHEN** 调用方按发布的 Skill 配置平台地址和凭证
- **THEN** 可以使用同一套说明完成真实设备认领、连接、截图/操作、续租和释放，不依赖未交付的辅助脚本或占位接口

#### Scenario: 安装客户端 Skill 包
- **WHEN** 调用方解压并安装发布的 `droidharbor` Skill 目录
- **THEN** 按该目录选择 `scripts/windows-amd64/droidharbor-cli.exe` 或 `scripts/linux-amd64/droidharbor-cli` 的绝对路径，Linux 首次赋予可执行权限；无需另行下载 CLI 或写入全局 PATH，原生 ADB 仍由调用机提供

#### Scenario: 领用保留应用状态的手机
- **WHEN** 新任务成功认领上一任务释放的手机
- **THEN** Skill 指导先观察当前画面/设备状态，不假定应用已关闭、页面已复位或账号重新登录

#### Scenario: AI 按用户指定的手机工作
- **WHEN** 用户指定设备名称，AI 使用 devices 列表确认设备并 claim --device-name 或 --device-id
- **THEN** 列表只包含名称、完整 ID、标签及连接/分配状态；指定手机不可用不换机，重名明确要求 ID，结果未知时用原目录、标签及选择条件重试


### Requirement: Windows/Linux 且不限制 harness
CLI SHALL 在发布矩阵中的 Windows/Linux 提供相同语义的命令、退出码和机器可读结果；MUST NOT 要求特定 harness 插件、父进程名称、内部 session 协议或结束钩子。

#### Scenario: 不原生加载 Skill 的运行器
- **WHEN** harness 只能执行标准命令并读取输出
- **THEN** 仍可按产品说明完成任务流程，不需要另建控制协议或安装专用插件

#### Scenario: 跨系统使用
- **WHEN** Windows 与 Linux 调用方分别执行同一任务流程
- **THEN** 认领、续租、连接状态和错误语义一致，路径及进程管理差异不泄露为业务合同差异

### Requirement: 每任务独立本地 ADB 环境
CLI MUST 为每个任务使用独立本地 ADB Server、任务密钥/配置和 loopback 设备入口，显式选择本租约目标；MUST NOT 修改或终止调用机默认 ADB 实例，也不得自动连接无关本地设备。Windows 保留官方原生调用，允许官方 adb 读取默认用户密钥及缺失时生成，但 CLI MUST NOT 覆盖或删除已有默认密钥，也 MUST NOT 宣称环境变量已隔离 Windows 默认用户配置目录。

#### Scenario: 两个任务同时运行
- **WHEN** 同一调用机同时连接两个有效任务
- **THEN** 两者命令使用各自实例和设备身份，不能因默认设备选择而操作另一任务手机

#### Scenario: 调用机已有 ADB 工作
- **WHEN** CLI 启动或清理任务时调用机已有独立 ADB 实例和本地 USB 设备
- **THEN** 该实例和设备连接不被 CLI kill-server、清理全部转发或自动抢占 USB 所破坏

#### Scenario: Windows 默认密钥与任务密钥同时存在
- **WHEN** Windows 原生 adb 同时加载默认用户密钥和 CLI 生成的任务密钥
- **THEN** 平台仅接受登记任务密钥的认证，不将默认密钥授予任务权限，且用户无需手工管理任务密钥

### Requirement: 连接进程不自动续租
CLI SHALL 按任务运行连接进程，不建立全局常驻守护服务；续租必须由调用方显式命令触发。Skill SHALL 说明长操作期间也要在 15 分钟内续租，正常完成显式释放。

#### Scenario: 长命令期间显式续租
- **WHEN** 任务需要执行超过单次租期的长操作
- **THEN** 调用方可在连接持续运行时另行发出 renew，连接进程本身不会暗中延长租约

#### Scenario: 运行器未发送结束通知
- **WHEN** harness 异常退出且 CLI 没有收到结束钩子
- **THEN** 不再发生隐式续租，服务端仍在现有有效期结束时撤销访问

### Requirement: 明确结果与版本兼容
CLI SHALL 提供稳定机器可读管理结果，保留原生 adb 的真实输出和退出语义，并明确区分认证、设备不可用、租约终止、协议不支持及结果未知。发现必要版本不兼容 MUST 失败，不后台自动升级。

#### Scenario: 平台与 CLI 不兼容
- **WHEN** 建连发现双方没有兼容的必需协议版本
- **THEN** CLI 返回明确错误，不启动假连接、不静默升级或切换原始 ADB 端口

#### Scenario: 设备动作结果不确定
- **WHEN** 操作发送后连接中断且无法确认手机是否执行
- **THEN** CLI 报告结果未知，不自动重新认领、换手机或重放该操作

### Requirement: 定向本地清理与秘密保护
CLI SHALL 只清理本任务可核验归属的进程、端口和工作文件，并保护任务凭证，不将秘密写入普通日志或输出。产品 MUST 明确共享调用机可信、不提供本机任务沙箱；原生 ADB Server 的本地客户端没有任务认证，旧命令在端口复用后误用新 Server 不在隔离保证内。不互信任务需要独立网络环境，仅更换 OS 用户不足以隔离 loopback TCP 访问。

#### Scenario: 正常释放与连接退出
- **WHEN** 任务释放租约并停止连接进程
- **THEN** 服务端访问终止，本任务本地入口和专用 ADB 被清理，其他任务继续使用

#### Scenario: 崩溃后端口或 PID 被复用
- **WHEN** 后续 CLI 根据旧任务记录处理残留资源，但原 PID/端口已属于其他进程
- **THEN** CLI 不误杀或清理该进程，并明确报告不能确认归属的资源

### Requirement: 任务连接就绪与首次带标签认领
产品 Skill SHALL 在首次 claim 中携带用户指定的全部标签；没有满足条件的可用设备时报告结果。调用方 SHALL 等待 `connect` 已核对原生 ADB 在线、平台连接活动且释放任务目录锁后发出的就绪 JSON；后续命令复用该任务连接。

#### Scenario: 已指定标签且没有可用设备
- **WHEN** 调用方收到明确的设备标签
- **THEN** 第一次认领就包含该标签；认领失败不去掉标签重领，不把标签当作已安装应用或登录的证据

#### Scenario: 收到就绪信号后立即操作
- **WHEN** 连接进程输出就绪 JSON 后立即运行应用命令
- **THEN** 该命令可以核验当前任务的活动连接，不依赖固定睡眠或等待 `connect` 退出，不争用发出就绪信号的连接目录锁

### Requirement: 应用启动、观察及可验证操作
CLI SHALL 在当前任务连接上提供应用启动、控件查找、只观察等待、输入及点击。条件由调用方给出，使用实际前台状态、控件及字段值。应用业务路径由业务 Skill 负责。

#### Scenario: 打开已安装应用
- **WHEN** 调用方指定应用包名
- **THEN** CLI 解析当前安装版本的 launcher 并使用该结果启动，返回真实前台组件和首个前台画面；指定业务页面条件时在同一调用中另行验证，应用已在前台不代表业务页面就绪

#### Scenario: 替换搜索词
- **WHEN** 调用方准备将已有文本替换为新值
- **THEN** CLI 先确认唯一目标是当前已聚焦且可编辑的控件；已有文本时先确认同一编辑器中的旧值已全选，再一次写入，并从同一编辑器读取并精确核对实际值；不会隐式提交，也不把原生退出码当作实际值

#### Scenario: 点击进入指定页面
- **WHEN** 当前页面提供唯一可操作目标且调用方提供结果条件
- **THEN** CLI 根据本次观察点击一次，随后只观察预期前台组件或控件；不把预先已满足的同一条件、广告、动画或加载变化当作操作成功

#### Scenario: 多候选、动态页面与超时
- **WHEN** 查找得到多候选、得不到可靠界面树或截止时间前预期条件不满足
- **THEN** CLI 只返回匹配候选的最小证据，不在歧义时执行动作；得不到可靠控件证据时返回当前截图并标记未能自动验证；超时返回最后观察，区分未发出、已发出但未证实和送达未知，等待过程中不重放动作

#### Scenario: 搜索受输入限制或登录失效
- **WHEN** 设备不支持所需原生输入、控件不可安全编辑或应用要求登录
- **THEN** 工具和 Skill 明确报告限制，保留账号、键盘与动画设置；登录由用户处理

#### Scenario: 在支持的编辑器输入中文和 ASCII 混合文本
- **WHEN** 有效任务在当前前台有唯一的普通文本编辑器，且 Android 和该控件支持原生整字段动作
- **THEN** CLI 核对当前窗口、编辑器和原值，区分占位符与实际内容；已有内容先确认全选，再派发一次单行编辑。同一 View 重建输入法连接不等于换字段，必须从同一编辑器读回精确值才报成功；操作不写剪贴板、不切换输入法、不安装 APK、不提交字段

#### Scenario: Unicode 编辑失败或送达未知
- **WHEN** 编辑渠道不可用、窗口或编辑器变化、任务授权失效、送达未知、或读回不一致
- **THEN** CLI 报告实际阶段及证据，不重放写入，不改用剪贴板、键盘或新任务连接；写入超时不代表 Android 未收到

### Requirement: 在有效任务内限量读取列表
CLI SHALL 在当前任务连接上按调用方提供的同 App 可见页面标记、唯一可滚动列表和直属条目条件读取 Android 界面树，从当前屏开始输出完整可见条目的文字与描述。命令 MUST 限制屏数、输出和总时长，并明确停止原因。

#### Scenario: 在同一商品列表读取多屏
- **WHEN** 页面条件成立，调用方允许读取多屏且相邻屏存在唯一连续重叠
- **THEN** CLI 在列表范围内慢滑，每次只滑动一次并重新验证页面，将新条目按观测顺序追加；仅移除确认的相邻屏重叠，保留其他位置的同名条目，不纳入列表外控件或未完整可见的边缘条目

#### Scenario: 限量、末尾和证据中断
- **WHEN** 达到屏数、输出或时限，列表没有进展、重叠缺失或不唯一，页面变化、界面树不可读或滑动送达未知
- **THEN** 停止并保留此前已确认条目，不重放滑动；只有列表存在可核验条目，指定的末尾控件出现在最后可见条目之后，且读取未失去连续性时才确认到达末尾，不推断起点以上的条目

#### Scenario: 观察一屏或初始页面不匹配
- **WHEN** 调用方只请求一屏，或当前页面、可滚动列表和可读条目的条件未核验
- **THEN** CLI 不发送滑动；有效的一屏返回实际条目，不匹配明确报告未验证
