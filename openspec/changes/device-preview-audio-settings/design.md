# Design

## Context

见 proposal.md。现有 React/shadcn/Base UI 页面和 Pion/H.264 采集是基线，用户要求直接改现有页面，不制作原型。schema 4 增量迁移、独立音频、像素倍率及媒体声音范围已确认；本轮用户批准 schema 5 新增增强上限，确认音量条随输出位置切换。

## Goals / Non-Goals

**Goals:** 六项需求端到端完成，沿用认证、统一通知、资源归属账本和十五秒保留。

**Non-Goals:** 麦克风、铃声/闹钟/通知静音、录制、路由自动修改系统音量、TLS、移动端或另一套界面。

## Decisions

### 登记删除

设备行增加 removed_at，保留历史 FK、幂等认领和单调 generation；删除先设置维护并验证当前占用代次，结束任务、人工访问和该设备自有进程，全部确认回收后移除。过程中禁止新分配；失败保留可管理的设备且通知。已移除链路不自动上线，显式重新添加核验相同硬件后恢复登记，默认不可分配。禁止物理删除历史或操作外部 scrcpy。

### 系统偏好与现有页面

新增独立 system_preferences 单例，保存 audio_default、window_scales JSON 和 revision；保持 global_video_settings 画质版本语义。系统设置组合原全局画质组件和新增偏好表单，独立保存，统一通知。现有工作台卡片改左右两列，右列包含名称、状态图标、指标及元数据，逐设备小窗按钮不嵌入其他按钮。

工作台无有效选择时，按在线优先、其余保持原顺序选择第一台；记录该选择，之后设备状态刷新不擅自换机。整卡由现有 ToggleGroupItem 负责点击与键盘，小窗图标是独立兄弟按钮且位于卡片右上角，不嵌套按钮或冒泡切换主设备。设备池维持图片和预览按钮导航。充电图标仅由 chargingStatus=charging 显示绿色，接电但未充电、充满、未知均灰色，电量数字保持。

### 单小窗和尺寸

同源 SharedWorker 串行管理唯一小窗的创建、复用及关闭登记；原生窗口名仅用于创建，不能单独承担跨独立标签页互斥。窗口消息切换目标，关闭创建者仍可使用小窗；关闭小窗释放登记。直接用登记视频尺寸及全局第一档预计算，倍率按钮左键循环、Base UI ContextMenu 右键选档；超过桌面完整缩放并提示，复用小窗保留当前倍率。流生命周期和原始像素定义分离，不把窗口缩放当作采集画质。

### 独立音频

复用 capture.Manager 的日志、原生启动门和严格资源回收，增加 audio-only 角色及 scrcpy-audio 账本种类。输出源 output，Opus 48 kHz/双声道/128 Kbps，经 Pion 音频轨道转发，不服务端转码、不新增服务。网页生成的接收 offer 显式声明 stereo=1 与 maxplaybackrate=48000，服务端声明双声道发送，避免浏览器默认单声道；保留其他编解码参数、视频及控制协商。设备模式停止自有输出采集，静音模式采集并丢弃，网页模式发给被授权的前台窗口。音频操作串行化，不获取视频更换锁长时间阻塞视频；最后视频成员关闭时停止并重置，十五秒保留中保持。音频错误具名日志和统一通知，禁止静默切设备播放。

音频 RTP 时钟以首包 PTS 锚定，随后按 Opus TOC 的真实包采样数递增，包括临时静音期间的已采集包；不把每包抖动的采集时间直接作为播放采样时钟。保留原始编码数据与当前顺序/路由，不靠丢包补偿或增加缓冲掩盖时间线空洞。非法时长明确终止并记录，支持 Opus 的合法帧长和多帧包，最大 120 ms。

主预览和小窗均将音频图标菜单放在左侧竖栏、返回/Home/最近任务之前，沿用现有 Base UI Select 和真实音频状态；移动入口不改变生命周期或音频控制协议。

### 主音量和网页增强

主音量条位于输出选择上方，沿用 Base UI Slider；顶部加减入口移除。网页主音量 0–100%，仅当前预览本地生效；设备播放读取并设置 Android STREAM_MUSIC 的真实当前值及范围，指针释放后提交一次绝对值并读取实际结果，不伪造连续音量值。静音时禁用，不因调音量改变路由或重建视频。

设备音量 API 绑定人工媒体会话，复用 SessionScope 与 scrcpy 音量键、shell_v2 真实读数授权；写入须为前台控制会话且当前设备播放。用户确认通过读数及加减达到目标，不新增 Android helper 或 DEX。确认普通媒体音频模式后，逐步发送原生加减并读取真实值，首次按键未改变不视为成功；按实际范围限制步骤并受请求期限约束，未达到目标明确报错。原设备链路失效或切走取消操作，不因读数失败估算音量，不改路由或视频。

网页媒体经 Web Audio 增益节点输出，主音量比例乘增强倍率，参数平滑过渡；增强默认 1.0，0.0 静音，超过 1.0 允许放大但可能失真。主音量和增强复用相同 Base UI Slider、竖向高度及样式，共用一个容器，悬浮或键盘焦点进入时向右展开，主条和手机布局保持原位，不使用独立浮层。只有网页播放可调增强。会话停播、后台及关闭时断开输出并清理自有 AudioContext，无重复原始音轨出声；浏览器拒绝启动明确通知。

system_preferences 新增 audio_gain_max，默认 3.0，有限且至少 1.0；复用偏好 revision 与跨窗口事件。下调上限时当前增强立即限制到新上限并统一通知；临时音量与增强不存库，同一预览保留期内保持，新建预览恢复 100%/1.0。

### 小键盘输入

浏览器 Numpad0–9 映射为 Android NUMPAD_0–9，并在每次 keydown/keyup 的 metaState 中带上 getModifierState('NumLock') 对应的 META_NUM_LOCK_ON（0x200000）。用户确认只验收 NumLock 开启时的数字输入，关闭时沿用既有按键路径，不增加导航转换；抬起使用按下时记录的 keyCode，不通过强制文本粘贴替代按键。

### 兼容与部署

Android 11+ 原生输出支持按真实结果判断，Android 11 启动可能要求屏幕解锁；没有 Opus 编码器或网页 autoplay 被拒绝明确报告。启动事务自动升级 schema 5，保留设备、历史及已有偏好，新增增强上限。release/ 只交付最新 EXE + Skill ZIP，回退使用升级前匹配数据库备份。

## Risks / Trade-offs

- REMOTE_SUBMIX 不覆盖铃声、闹钟和通知；用户已选只处理媒体声音，路由切换不自动更改系统音量，设备音量条仅按用户操作调整媒体音量。
- 独立音频多一个原生进程，换路由不重建视频；需真实设备检查默认静音、路由切换、十五秒和失败通知。
- 浏览器可能限制弹窗、置前和 resizeTo，失败明确通知并允许用户手动调整；不承诺 OS 强制置顶。
- 删除在离线且残留未核验时不能完成，需恢复链路后重试，不能假清理。
