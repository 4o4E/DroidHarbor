## 构建

Windows 在项目根目录运行；若 Go 已在 PATH，可用 `go` 代替项目路径。

```powershell
npm --prefix web ci
npm run web:build
npm run assets:prepare
.tools/go/bin/go.exe build -o bin/droidharbor.exe ./cmd/droidharbor
.tools/go/bin/go.exe build -o bin/droidharbor-cli.exe ./cmd/droidharbor-cli
bin/droidharbor.exe version
bin/droidharbor-cli.exe version
```

前端开发使用 `npm run web:dev -- --host 127.0.0.1`，Vite 不自动代理 API。完整功能通过 Go 的同源 HTTP 入口验收。正式构建通过 `npm run assets:prepare` 将 `web/dist` 和已校验的 scrcpy-server v5.0.1 复制到被 gitignore 的内嵌资源目录，Go 构建/测试前须准备一次；网页变更后重新构建并准备。运行时不依赖源码、外部前端目录、scrcpy 文件或 Node/Go。

Windows 用 `npm run package:windows` 一次构建并分别分发服务端、客户端，输出根目录为 `release/windows-amd64-时间戳`。`DroidHarbor-server-windows-amd64.zip` 包含内嵌网页和 scrcpy-server 的平台 EXE、零参数 CMD 入口、可选管理员初始化入口、`.env.example` 及[服务端说明](../deploy/windows/README.md)，部署在连接手机的机器；`DroidHarbor-client-windows-amd64.zip` 包含任务 CLI、产品 Skill 及[客户端说明](../deploy/windows/README.client.md)，用于任务调用机。人工工作台使用浏览器，无需安装客户端。ADB 由外部环境提供，打包流程不配置域名、证书或网络基础设施。Linux Docker 构建也将资源内嵌，运行镜像只需复制平台二进制。

## 数据库

schema 已经用户明确批准。迁移使用 WAL、FULL 同步、外键、IMMEDIATE 写事务和单连接；网络或设备 I/O 不进入事务。只有空库或已识别迁移历史可以初始化/升级；未知版本、无历史的已有数据库、执行失败均报错，不重建覆盖。

```powershell
bin/droidharbor.exe migrate --database .local/dev/pool.db
```

本命令不连接手机。数据库默认包含 9 张业务表和迁移记录；并发占用的最终保障包括 active device/task 部分唯一索引、设备代次唯一、caller 作用域幂等键及任务/caller 复合外键。

`serve` 和 `migrate` 都先获取数据库规范路径对应的 OS 文件锁，再打开数据库。第二个进程会直接失败，不同时服务或迁移同一库；平台停止后可重新获取。保留 `.process.lock` 文件是正常行为，不能通过删除锁文件绕过检查。本机已实际验证“服务运行时另一个 migrate 被拒绝、停止后 migrate 成功”。

## .env、HTTP 与首次启动

服务端无参数默认启动平台，直接读取 EXE 同目录 `.env`；`start.cmd` 只启动 EXE，不拼接运行参数。发布包提供 `.env.example`，复制后即可使用，无需填写服务器 IP。媒体默认通过 WebRTC 自动收集本机 IPv4 host 候选，包括回环地址，浏览器自行选取可达路径；`DROIDHARBOR_RTC_ADVERTISED_IP` 仅用于显式覆盖。默认 HTTP `0.0.0.0:8080`、UDP `0.0.0.0:8081`、外部 ADB `127.0.0.1:5037`。

从源码构建后，将模板复制到 `bin/.env`，然后直接运行：

```powershell
Copy-Item deploy/windows/.env.example bin/.env
# 仅在首次缺失配置时复制，不覆盖已有部署配置。
bin/droidharbor.exe
```

- `.env` 使用标准 dotenv 解析，支持注释、引号、CRLF 和 UTF-8 BOM；进程环境中的同名变量优先。数据库、管理员摘要、上传暂存、日志及资源覆盖路径均相对该配置文件目录解析，不依赖启动工作目录。
- 应用原生提供 HTTP/WS，不配置 TLS、证书、私钥或固定 origin。HTTP 不加密网络内容，运行于可信内网/隔离网络；认证仍由管理会话、调用凭证、任务授权和 CSRF 执行。浏览器 Origin 的主机/端口自动与本次请求 Host 比较，不信任任意反向代理头；如有外部代理，须保留原 Host。
- 缺少 `.env` 时提示复制模板；格式、类型或显式地址覆盖无效时指出配置名称并非零退出。点击 `start.cmd` 失败会保留控制台供查看，不要求补一长串启动参数。
- 首次启动在管理员摘要文件不存在时独占创建高熵凭证，`admin_credentials_initialized` 日志同时向控制台和文件交付 `adminToken`，不受普通运行日志级别过滤。已有凭证复用且不重复输出 token，文件损坏/格式错误明确失败，不覆盖重置；`admin_credentials_ready` 与 `database_ready` 记录凭证和数据库就绪。初始化日志含登录凭证，按凭证资料保护并在分享前移除该字段。
- 仍可使用 `admin-init --admin-file <新文件>` 显式初始化/轮换，再修改 `.env` 的 `DROIDHARBOR_ADMIN_FILE`。旧摘要版本不跟随新凭证继续认证。数据目录应仅允许运行账户访问，Windows 使用专用目录 ACL，Linux 使用文件权限。
- 网页登录 `POST /api/v1/admin/sessions`，正文为 `token`。浏览器获得 `droidharbor_admin`、HttpOnly、SameSite=Strict Cookie 和 CSRF token；Cookie 可在 HTTP 发送，写操作仍验证 Origin/CSRF。会话默认 12 小时，配置 `DROIDHARBOR_ADMIN_SESSION_TTL`；`GET/DELETE /api/v1/admin/sessions/current` 用于恢复/退出。
- 日志由 `DROIDHARBOR_LOG_FILE` 和 `DROIDHARBOR_LOG_LEVEL` 配置，默认 `logs/platform.jsonl`、info。文件与控制台双写，20 MiB/文件、最多 5 份压缩历史；创建失败退出，写入失败直接报告 stderr。debug 记录 requestId、匹配路由和耗时，不记录原始 URL、查询参数或正文。
- 启动事件包含 revision、dirty 标记、Go 版本和 PID。故障包含阶段/错误码、关联 ID、安全原因链、OS errno 或 SQLite code；不原样输出设备或 SQL 错误正文。HTTP panic 记录类型/调用栈并中止异常连接，不伪装成功。
- 外部 ADB Server 由部署环境提供，`DROIDHARBOR_ADB_SERVER` 指向它；平台不自动启动、停止或替换默认 ADB。另有明确的 `adb-serve --adb <绝对路径> --listen 127.0.0.1:<port> --log-file <绝对路径>` 专用 runner，仅在需要独立管理实例时显式使用。
- 官方 SDK 37.0.1 的 runner 使用 `-L tcp:<port>`，不接受 `tcp:127.0.0.1:<port>`。隔离无手机验收可显式禁用 USB/模拟器/mDNS；正常部署不使用这些隔离设置。两种 ADB 实例不能争用同一 USB 手机。
- `/health/live` 只表示 HTTP 进程响应，不表示设备、网关或媒体已就绪；浏览器能打开网页也不能代替投屏/控制验证。
- 当前受控 Chromium 已用局域网 IP 的纯 HTTP 页面登录并解码两台真机，不要求 HTTPS。该页面 `isSecureContext=false`、`RTCPeerConnection` 可用，但浏览器系统剪贴板 API 不可用；工作台“复制到电脑剪贴板”会明确报错，可手动选择文本复制。手机剪贴板通道与浏览器系统剪贴板是不同能力，不能混为媒体连接失败。


API 合同见 [OpenAPI](../api/openapi.yaml)。目前只列出已实现入口，其他规划接口仍见工程设计，不返回假成功。

## 调用凭证与能力查询

- 管理员使用 `POST /api/v1/callers` 创建命名调用凭证，正文为 `{"name":"调用方名称"}`，同时携带会话 Cookie、Origin 和 CSRF token。`token` 只在创建响应中出现；数据库只存摘要。丢失秘密后撤销该凭证并重新创建，不提供找回。
- `GET /api/v1/callers` 仅供管理员读取名称、标识、创建时间和已持久化撤销时间，不返回秘密或摘要。
- `GET /api/v1/capabilities` 接受管理员 Cookie 或 `Authorization: Bearer <调用/任务秘密>`；CLI 调用不需要浏览器 Origin。显式 bearer 无效时不改用同请求的 Cookie。响应只提供 API major、平台和功能可用性，不暴露其他任务身份或设备管理地址。
- `GET /api/v1/capabilities` 按当前服务 wiring 报告 `remoteAdb`、`webRTC`、`fileTransfers`；CLI 与 WebSocket 原生 ADB 网关、人工媒体及文件传输后端已实现。`appium`、`uiautomator2` 仍为不可用/预留。能力为实现声明，不等于设备在线、任意 Android 或生产矩阵验收。
- `DELETE /api/v1/callers/{id}` 需要管理员会话、Origin 和 CSRF token。认证、租约、撤销统一由租约管理器负责；先取消关联任务授权，再持久化撤销和结果记录。设备只在平台资源确认清理且连接健康后回池，不把撤销本身当作清理成功。
- 撤销写库失败返回 503，但当前进程仍拒绝对应调用方/任务访问。修复存储故障后必须显式重试撤销；不能把重启或列表中的 `revokedAt: null` 当作撤销成功。重复撤销已存在且已撤销的凭证返回 204；不存在的标识返回 404。
- 创建/撤销结果写入 `operation_records`，运行日志记录 requestId、错误类别及不透明标识；不记录凭证名称、秘密、完整请求正文或底层数据库错误正文。创建与结果记录同事务提交，记录失败不会交付新凭证。
- 首次认领原子绑定任务秘密；同一 caller 的不同 task 不能互访。人工媒体使用独立管理员会话，不从 AI 租约创建或续租；原生 ADB 通道以任务 bearer 和租约/连接代次授权。

## 设备接入与租约控制面

以下接口均以 `/api/v1` 为前缀，字段和响应见 OpenAPI：

1. 管理员用 `GET /device-discovery` 读取实际 ADB 快照。未知设备不会被自动执行属性查询或开放分配；未授权、离线或发现源失效均不能用于认领。
2. `POST /devices` 登记名称、`kind` 和 `endpoint`，生成稳定 deviceId/linkId，初始维护且未核验。同机第二条链路使用 `POST /devices/{id}/links`，不因新 IP 自动创建第二个可分配名额。
3. Wi-Fi 先按需执行链路 `/pair`，提供手机显示的 `pairingEndpoint` 和临时 `pairingCode`；再用 `/connect` 显式连接已登记 endpoint。两个端口不是同一概念。码不保存；外部动作前记录操作，无法确认结果时返回 `ADB_RESULT_UNKNOWN`，不能自动重试。
4. 链路 `/verify` 从明确 transport 读取硬件 serial、制造商、型号、product 和 Android 信息；跨链路硬件属性必须一致，同一 serial 已属于其他 deviceId 时拒绝。核验成功不会自行解除维护。
5. 读取设备 `version` 后 `PATCH /devices/{id}`。名称/标签与 `maintenanceRequested` 分别提交；标签去首尾空白、去重并按全部要求精确筛选。旧版本返回 409；重启后旧配置版本失效。维护启停复用租约撤销/回收路径，不直接把占用中设备设为 available。
6. 调用凭证用 `POST /leases` 提交 caller 范围的 taskId、预先保存的 64 位十六进制随机 taskSecret、requiredTags 和 `Idempotency-Key`。响应丢失后重发同一请求取得原结果；不能换秘密或幂等键自动多领。无匹配失败不会留下半绑定任务。
7. 本任务 bearer 调用 `GET /leases/{id}`、`POST /leases/{id}/renew`、`DELETE /leases/{id}`。初次和每次显式续租均为处理时刻起 900 秒，不叠加剩余时间；不接受 ttl，不自动续租。共享 caller 和同 caller 的其他 task 无权访问；管理员可以查看/终止，不能代替任务续租。
8. 释放/到期先取消运行授权，再持久化并回收。写库失败不恢复授权；修复后显式释放或授权的恢复操作可补写终态。回收中返回 202 及状态，健康未确认时不回池。管理员可调用设备 `/recover` 重新核验，不能绕过尚未确认清理的资源。

无线连接端口变化时，用 `PATCH /devices/{id}/links/{linkId}` 提交当前设备 `version` 和新 `endpoint`。原 deviceId/linkId 与硬件身份保留，旧数据流失效；新地址须再次显式 connect/verify，已有租约不自动换路。旧地址可重新登记给实际使用它的设备，不永久积累地址占用。迟到的 connect 结果不能恢复已经被替换的地址。

普通任务 bearer 写请求不要求浏览器 Origin/CSRF；管理员 Cookie 写请求仍必须两者匹配。显式 bearer 失败不回退到 Cookie。设备列表仅给 caller 返回选机摘要，不含真实链路、维护配置版本或其他任务信息；任务秘密不能枚举设备池。

- 链路断开使旧代次失效；不自动切换另一条链路、不重放动作，尚未到期租约仍须显式续租并显式重建连接。scrcpy 采集资源（服务进程身份、私有 socket、平台专属 JAR）有持久化 ownership journal；只在原核验链路仍有效、所有权探测吻合且清理结果确认后标记清理。未知/旧启动资源无法确认时保持隔离、不回池；不会清理应用、业务文件或未知的其他进程。不得把连接断开记作媒体 session 正常结束验收。

## CLI 管理命令

CLI 已交付 `version`、`capabilities`、`claim`、`status`、`renew`、`release`、前台 `connect`、`env`、`disconnect`；仓库随附可用的产品 Skill [`skills/droidharbor/SKILL.md`](../skills/droidharbor/SKILL.md)。这些命令/Skill 不代表正式发行支持矩阵已完成。

把创建调用凭证的 JSON 响应保存到仅当前用户可读写的文件，文件包含 `token`；不要把秘密写进命令行或 URL：

```powershell
bin/droidharbor-cli.exe capabilities --server http://localhost:8080 --credential-file .local/dev/caller.json
```

每个任务使用独立目录；`--tag` 可重复，设备必须满足全部标签：

```powershell
bin/droidharbor-cli.exe claim --server http://localhost:8080 --credential-file .local/dev/caller.json --task-dir .local/dev/task-a --task-id job-a --tag account-a
bin/droidharbor-cli.exe status --task-dir .local/dev/task-a
bin/droidharbor-cli.exe renew --task-dir .local/dev/task-a
bin/droidharbor-cli.exe release --task-dir .local/dev/task-a
```

Linux 使用同名无 `.exe` 的二进制和相同参数。任务父目录须已存在并配置专用权限。CLI 在首次认领前保存随机任务秘密、幂等键及规范化参数，不保存 caller token；Linux 任务目录/文件分别为 0700/0600，权限过宽直接拒绝。同目录并发命令返回 `TASK_BUSY`，不无限排队。长任务必须由调用方显式 renew；这些短命令不启动 ADB。

首次认领返回 `RESULT_UNKNOWN` 时，保留原目录，用相同 server、caller 凭证、taskId 和标签显式再次运行 claim；它复用原任务秘密与幂等键，不新领设备。已有任务不能改用其他参数或覆盖非空目录。renew/release 结果未知时先 status，不自动重放写请求；结束后再次 claim 原请求只返回原租约终态。

CLI 接受管理员提供的 HTTP(S) 服务地址，不再提供证书/CA 参数，不跟随重定向。HTTP 在可信内网/隔离网络使用；外部标准 HTTPS 入口沿用系统信任，不修改信任库。Linux 凭证文件为 0600，Windows 使用运行账户专用目录 ACL。

Windows 任务目录保护只授予当前运行用户完整控制并关闭权限继承；目录/文件已属于当前用户时仅更新 DACL，不重复设置 owner。否则普通用户拥有目录但没有 `WRITE_OWNER` 时也会被 Windows 拒绝。文件和目录的实际 ACL 回归已通过，不要求为此提升到管理员。

成功 JSON 写 stdout，错误 JSON 写 stderr，并保留可取得的服务端 requestId。退出码：0 成功、1 输出失败、2 参数/本地配置错误、3 身份/权限失败、4 连接或服务响应失败、5 能力/业务状态冲突（含目录忙、无匹配设备或租约结束）、6 写操作结果未知。能力/状态查询不隐式认领或续租。

Windows 和 WSL Linux 原生 CLI 已分别对实际 HTTPS 平台执行 claim/status/renew/release；初次期限 900 秒、显式续租、释放回池及终态重发不再分配均已观察。Linux 另验证目录/文件权限及过宽权限拒绝。Windows 通过临时 HTTPS 代理丢弃平台已成功认领的首个响应：CLI 返回 exit 6，SQLite 只有一条租约，本地保留原秘密/幂等键；显式重发恢复同一 leaseId，未多领。后续原生 ADB 数据通道也已在自建协议端点及 USB/Wi‑Fi 两机验收，仍不代替性能与长稳证据。

能力查询覆盖 HTTP 地址、身份错误、重定向不转发凭证及 API major 不兼容。HTTP 保留连接复用，已消费的写请求正文不可自动重放；CLI 本身没有自动重试循环。

### 原生 ADB 长连接

使用普通 harness 的后台进程功能保持以下前台命令运行，不需要专用插件或结束钩子：

```text
droidharbor-cli connect --task-dir <私有任务目录> --adb-bin <原生adb绝对路径>
droidharbor-cli env --task-dir <私有任务目录>
```

`connect` 只有在指定原生目标在线后才输出就绪 JSON。执行设备命令必须完整使用当前 `env` 返回的 `adbBinary` 和 `adbArgs`，保留显式 host、Server 端口及设备 endpoint，不使用默认 ADB 实例或旧端口。任务进程和普通流量都不自动续租；长操作期间另行显式执行 `renew`。

结束时先 `disconnect` 再 `release`。直接释放租约也会撤销已有流，但不代表已到达 Android 的动作没有副作用。`exec-out` 没有远端退出码协议，断流时原生命令也可能退出 0；必须核对完整输出，不能据此宣称执行成功。二进制截图和文件的 Windows/Linux 用法见[产品 Skill](../skills/droidharbor/SKILL.md)。

### 人工媒体、原始截图与文件传输 API

这些接口是已实现的后端能力，均使用管理员网页会话；写请求还必须带匹配的 `Origin` 与 `X-CSRF-Token`。媒体/传输 API 不接受 caller/task bearer。创建 `POST /api/v1/devices/{deviceId}/sessions` 时提交 `{"mode":"readonly","offer":"<浏览器 SDP offer>"}` 或 `mode: "control"`；协商返回 SDP answer 和候选信息，增量候选走 `POST /api/v1/sessions/{sessionId}/candidates`，结束走 `DELETE /api/v1/sessions/{sessionId}`。一台设备的观看者共享一份 scrcpy 采集，媒体会话不创建、续期或暂停 AI 租约。

- `readonly` 会话可以看视频和下载截图；设备输入、剪贴板操作、文件上传/安装及将设备参数应用到该只读会话均拒绝。`control` 会话允许受控输入。输入归属到各自观看会话，关闭某观看者只释放其按住的输入。画面旋转/采集重启会增加 `captureEpoch`，旧代次画面坐标输入拒绝；收到 `dispatched` 只代表已交给设备通道，不等于设备操作已确认。剪贴板读取须等待 `clipboard.result/received`，写入须等待 `clipboard.result/acknowledged`；设备 ACK 不证明目标应用已应用文本，`unknown` 不得自动重放。
- `GET /api/v1/devices/{deviceId}/video-settings` 读取请求参数、实际生效参数及状态；管理员以 `PATCH` 和当前 `revision` 更新 `maxSize`、`maxFps`、`bitRate`。修改影响同设备所有观看者；带 `sessionId` 时只允许其控制会话，不允许只读会话。设置写入后重建采集可能失败，须读取最新状态，不自动重放输入或降档。
- `GET /api/v1/sessions/{sessionId}/screenshot` 返回该会话当前已核验链路上的原始 PNG（不缩放、不重编码、不复用视频帧），允许只读会话。响应含 `X-DroidHarbor-Image-Width`、`X-DroidHarbor-Image-Height` 和 `Cache-Control: private, no-store`；读取中断的部分文件不可视为完整图片。
- 文件/安装先 `POST /api/v1/sessions/{sessionId}/transfers` 创建 metadata，再以 `PUT /api/v1/transfers/{transferId}/content` 流式上传完整 `application/octet-stream` 正文，`Content-Length` 必须精确等于 metadata 的 `size`；`202` 只代表本地暂存完成，之后用 `GET /api/v1/transfers/{id}` 查询设备操作真实结果。`DELETE` 取消未完成工作。示例普通文件请求：`{"fileName":"fixture.bin","purpose":"file","size":262181,"targetPath":"/sdcard/Download/fixture.bin","overwrite":false}`。默认不覆盖同名文件；只有显式 `overwrite:true` 才允许普通文件覆盖。APK 使用 `purpose:"apk"`，由设备 shell-v2 执行 `pm install -r -S <size> -`，可能替换同包应用；不支持 `targetPath`，取消也不保证撤回已开始的安装。
- 上传不接受 multipart、压缩正文或断点续传。默认上限为单文件 256 MiB、并发 8 个传输、shell 输出 64 KiB，分别由 `.env` 的 `DROIDHARBOR_TRANSFER_MAX_UPLOAD_BYTES`、`DROIDHARBOR_TRANSFER_MAX_ACTIVE`、`DROIDHARBOR_TRANSFER_MAX_COMMAND_OUTPUT` 调整（受服务端硬上限约束）。上传期间每次读数据会刷新 60 秒闲置超时，不设最低吞吐量。

Chromium 的 HTTPS→Pion→自有 smart-socket 模拟器 H.264 验收覆盖 3 个观看会话共享采集、晚加入、画质变更重启、画面旋转至 1920×864、stale epoch 输入拒绝及输入所有权。另观察到中文 clipboard SET ACK/GET、右键 scrcpy type 4 down/up；864×1920 原始 PNG 尺寸正确且 readonly 可下载，readonly 输入/参数修改被拒绝。文件夹具 262181 字节精确往返；默认 noclobber 在设备传输前失败且 `bytesTransferred=0`，显式 overwrite 成功。HTTP 上传阻塞期间结束所属会话后返回 `410 UPLOAD_CANCELLED`，另一观看者不受影响。底层模拟链路断开后，两个观看者的 DataChannel 均关闭，视频状态为 failed；重连不会复活旧会话。显式创建的新会话收到新代次并解码正确像素，最后一名观看者退出后视频回到 idle。这些结果不是 Android 编码器实际画质、真机性能或 APK 安装验收。

单观看者网络故障另以临时 UDP 中继实测：只丢弃该观看者的下行包，3 秒内丢弃 124 个数据报，其 RTP 接收包数保持 15；另一观看者持续解码 90 帧。恢复转发后，受影响观看者重新解码且原始红绿采样正确；结束全部会话后采集回到 idle。队列字节数/帧数上限及等待新关键帧期间拒绝旧代次确认另有行为回归。此检查覆盖受控丢包隔离，不是生产带宽、手机编码负载或持续运行性能结论。


## 部署用法与边界

服务从 `.env` 读取 HTTP、外部 ADB、WebRTC UDP4 和文件暂存配置，内嵌 scrcpy-server 与网页。应用不配置证书/域名，不自动选择 STUN/TURN、切换媒体路线或把 ADB 管理端口暴露给客户端。

### Linux Docker Compose

先准备 Compose 引用的宿主机目录：`DH_PLATFORM_DATA`（SQLite/transfer staging）、`DH_CONFIG_DIR`（`admin.json` 和从模板准备的 `.env`）和独立 `DH_ADB_AUTH_DIR`（专供容器 ADB Server 的 `.android` 授权数据）。不要把默认用户 ADB 配置直接挂载为共享授权。Compose 自身的 `deploy/.env` 至少设置：

```dotenv
DH_HTTP_BIND_ADDRESS=127.0.0.1
DH_HTTP_PORT=8080
DH_RTC_BIND_ADDRESS=127.0.0.1
DH_RTC_PORT=48000
DH_RTC_ADVERTISED_IP=192.0.2.10
DH_PLATFORM_DATA=/srv/droidharbor/platform
DH_CONFIG_DIR=/srv/droidharbor/config
DH_ADB_AUTH_DIR=/srv/droidharbor/adb-auth
```

把示例地址换成部署实际值，`DH_RTC_ADVERTISED_IP` 必须可从浏览器访问，RTC 端口同时用于容器内监听与宿主 UDP 发布。准备管理员摘要和配置 `.env` 后，从仓库根目录执行：

```sh
docker compose --env-file deploy/.env -f deploy/compose.yaml up -d --build
docker compose --env-file deploy/.env -f deploy/compose.yaml ps
```

Compose 使用平台与 ADB 的 `latest` 镜像；依赖版本仍由 Dockerfile/锁文件固定。平台读取挂载的 `.env`，Compose 环境覆盖容器内数据路径、ADB 端点和网络端口。ADB 5037 只在 `backend` bridge 内 expose，无宿主端口映射；仅发布 HTTP 和显式 RTC UDP。USB 热插拔及目标宿主网络仍须实测。既有独立平台更新/备份恢复证据不替代本轮 HTTP/dotenv 部署的目标环境验收。

`deploy/backup-linux.sh` 用法为 `BACKUP_DESTINATION PLATFORM_DATA CONFIG_DIR ADB_AUTH_DIR DROIDHARBOR_BINARY`，要求绝对路径；它暂停运行的 Compose 服务后停止态复制，随后恢复先前运行的服务。`deploy/restore-linux.sh` 用法为 `BACKUP_SOURCE PLATFORM_DATA_TARGET CONFIG_DIR_TARGET ADB_AUTH_DIR_TARGET DROIDHARBOR_BINARY`；目标必须不存在，恢复会停服务、复制并执行 `migrate`，完成后保持容器停止。可用绝对路径 `DH_COMPOSE_ENV_FILE=/path/to/deploy.env` 让这两个脚本读取 Compose 环境；切换到恢复目标后再显式更新部署配置。

更新前先备份，保留与备份匹配的发布版本。仅更新平台可执行 `docker compose --env-file deploy/.env -f deploy/compose.yaml up -d --no-deps --build platform`，不连带重启 ADB。回退涉及数据库时，使用匹配版本的备份恢复到新目录，再修改部署配置；不要用旧程序直接打开新 schema，也不要删除未知版本数据库来强行启动。实际验收已完成停止态备份、恢复后旧活跃租约变为 `ended/platform_restart`、旧任务续租返回 `410 LEASE_ENDED`、密钥逐字节一致；未知 schema 恢复失败且原数据保留。

### Windows 原生服务

管理员可运行 `deploy/windows/install-services.ps1` 安装固定服务名 `DroidHarbor` 与 `DroidHarborADB`。必填参数为 `BinaryPath`、`DataDirectory`、`ConfigDirectory`、`AdbExecutable`、`AdbListen`、`TransferDirectory`。`ConfigDirectory` 须包含 `.env`、`admin.json`；其中数据库/暂存目录须指向所授予权限的 `DataDirectory`/`TransferDirectory`，管理员文件指向 `ConfigDirectory/admin.json`，日志指向专属可写日志目录。平台 SCM 命令仅为 `serve --env-file <配置路径>`，HTTP/RTC 运行值均在文件中配置。安装器配置专用 virtual account、ACL、恢复策略和独立 ADB；本轮不宣称系统重启、自启动矩阵完成。

跨主机恢复时，先用 `backup-services.ps1` 创建备份；新主机用 `install-services.ps1` 的 `-NoStart -AdbAuthorizationSeedDirectory <备份目录>\adb-auth\.android` 注册服务但不启动，并将 seed 复制到仅 SYSTEM、Administrators 与 ADB service account 可读的受保护 staging 目录。然后以 `restore-services.ps1 -BackupSource <备份目录> -DroidHarborBinary <绝对路径> -PlatformDataTarget <新且不存在的目录> -ConfigTarget <新且不存在的目录>` 执行受控的首次 ADB readiness/key 校验。脚本只在实际服务 profile 内容完全一致且 seed 已从 SCM ImagePath 移除后清理 staging；冲突或失败不覆盖现有 key，保留 seed 与状态供显式处理。服务保持停止并设为自动启动；部署者须先让 SCM 命令行指向恢复后的数据/配置目录（或按目标路径重新注册服务），再启动/重启系统，不要运行仍指向空安装目录的命令行。

更新使用 `update-services.ps1 -NewBinary <新程序绝对路径> -InstalledBinary <已安装程序绝对路径>`，脚本停服务、保留旧程序并更新；启动失败时恢复旧程序。实际验收已覆盖正常升级、故意不可用的候选程序启动失败后恢复原程序及 HTTPS 可用。程序回退不等于数据库降级：若 schema 已迁移，必须用匹配备份恢复数据。停止态备份/恢复已在实际 SCM 服务上验证，旧活跃租约恢复后失效；授权 seed 的相同密钥校验、SCM 参数移除及 staging 清理已验证，尚未模拟全新主机的空 profile 导入。

Windows 官方 ADB 从服务 token 的真实 OS profile 读取 `.android\adbkey`（通过 `SHGetFolderPathW(CSIDL_PROFILE)`）；`HOME`/`USERPROFILE` 不能隔离其默认密钥。实际服务使用 `C:\Windows\ServiceProfiles\DroidHarborADB\.android`；不要覆盖 profile 中不相同的 key。ADB 子进程由 Windows Job Object kill-on-close 约束；Linux 平台拥有的 ADB 子进程使用 parent-death signal，创建线程保持到子进程退出。真实子进程的 Windows 退出/句柄竞争、Linux 创建线程寿命回归已通过；不据此宣称真机、系统重启、USB 驱动或完整生产矩阵已通过。

### 真机验收注意事项

- 默认 ADB Server 会占用 USB 设备。启动专用 `adb-serve` 前先停止默认实例；若专用实例启动时 USB 已被占用，释放后需重启专用实例才会重新枚举。测试期间不要执行默认 `adb` 命令，否则会重新拉起默认 Server 并再次抢占 USB。无线设备在专用实例上用显式 `connect` 接入。
- scrcpy 以 `power_on=false`、`stay_awake=false` 启动；屏幕熄灭时虚拟显示可能不产帧，表现为关键帧等待超时。投屏验收前唤醒屏幕，必要时临时设置 `svc power stayon true`，结束后恢复。
- `cleanup=true` 的 scrcpy helper 会在运行期 `unlink` 私有 JAR，因此 JAR 不存在不等于进程已退出。归属核验以 PID/start ticks 加进程 `CLASSPATH` 环境为准，清理必须接受 JAR 已被 unlink。
- Android 的 `adbd` 以 shell uid 运行但 environ 为 root-only。environ 扫描必须先按 `/proc/<pid>/cmdline` 过滤 `app_process`/`scrcpy-server`，不能把不可读 environ 一律判为错误；设备进程退出期间的瞬时 ADB 探测失败应在有界清理窗口内重试。
- 不要强制 `video_codec_options` 的 profile 或 I-frame interval：真机硬件编码器可能 configure 失败或无帧。默认 I-frame 间隔 10 秒大于 5 秒关键帧等待，新观看者/PLI 必须通过 `RESET_VIDEO` 请求关键帧；只读会话允许该恢复动作。

已实际运行 Windows HTTPS 服务完成设备登记、标签/版本冲突、信息过滤、不可用设备拒绝及单实例检查。另用隔离 ADB 协议夹具运行正向控制面：同设备并发认领只成功一个、幂等重发复用、固定期限与显式续租、共享 caller/兄弟任务拒绝、释放写库失败后禁止续租且显式重试成功、再次认领代次递增、撤销失败仍拒绝授权、旧幂等请求不重复分配。此处的身份控制面夹具只提供身份属性；媒体/视频验收另使用真实 HTTPS/Pion 与独立 smart-socket 模拟器，如上所述。

实际重启保留 active 租约的临时库后，旧租约以 `platform_restart` 结束且不能续租，新的 bootId 生效；没有当前健康链路的设备不回池，临时注入的未确认资源记录进入 quarantined。断开发现源时接口明确失败，未过期租约保留且允许显式续租。运行日志与操作结果检查未发现秘密或故障注入正文。

原生客户端实测及用户确认的运行边界：

- 共享调用机可信，首版不提供本机任务沙箱。原生本地 ADB Server 不认证发起命令的客户端；旧命令在端口复用后可能借助新 Server 的授权。独立任务密钥保护 Server 到平台网关的认证，不保护本机客户端到 Server 的访问。需要运行不互信任务时由部署者提供独立网络环境，仅换 OS 用户不够；平台仍拒绝旧任务凭证、旧密钥和失效代次直接访问网关。
- 保留 `expires_at > claimed_at` 数据库约束。时钟大幅回拨可能使续租失败，既有授权仍按原单调时钟期限结束，不自动延长或伪造 UTC 时间。运维修正系统时间后，只有尚未到期的任务才能显式重试续租；不改变 schema。

另实测显式 `adb -H 127.0.0.1 -P <端口>` 在指定 Server 不存在时直接拒绝启动，不会转去启动默认 Server。这不替代启动时的进程身份核对和任务资源归属。

原生 CLI 的定向清理已在 Windows/Linux 实测：仅终止经出生身份核验的 CLI 父进程，专属 ADB 子进程随之退出；显式恢复返回 closed，独立后端保持在线。Windows 使用 Job Object；Linux 通过进程启动身份及父进程退出信号约束。测试中的 pidfd/Windows 句柄只用于核验并终止自建验收进程，不用进程名或端口猜测后批量结束。Windows 的实际 PID/端口复用已验证：把一个自有无关监听进程的 PID 同时填入旧 owner/ADB Server 记录、出生身份保持旧值，disconnect 仍保留该进程及端口。此证据不代替 USB 或不互信调用机隔离验收。

## 状态通知与列表预览后端

- `GET /api/v1/events`：管理员 Cookie 或任务 bearer。共享 caller 凭证不能订阅；显式无效 bearer 不回退到 Cookie。每次连接先 resync，再读取权威快照；不承诺事件历史重放。任务仅收到自己的租约和当时分配设备的通知，正常结束后仍能读取自身终态，不接收设备后续任务变更。授权在事件发送前及空闲时最多每五秒重新检查。
- 通知总线不等待网络：最多 256 个订阅，每个队列 32 条；慢客户端断开后须重连刷新。运行期序号不替代配置 PATCH 的 version；路由 TaskID/DeviceID 不进入公共事件内容。
- `GET /api/v1/devices/{id}/preview`：仅管理员会话。对已有已核验链路按需采集，完整链路身份相同的请求共享工作，最短五秒采集间隔；不自动连接、不创建或续租 AI 任务。原始 PNG 限 32 MiB/1600 万像素，最多两个采集/处理任务；只缓存最长边 480 的 JPEG，状态键不超过 128、图像缓存不超过 16 MiB，闲置回收。不以旧帧兜底失败、断线或链路更换。
- 返回拍摄时间、设备及链路代次，缓存命中保留原拍摄时间。响应为 `private, no-store`。设备池与左侧列表已接入真实 JPEG、拍摄时间及默认五秒可见性调度；实际滚出可视区 6.2 秒没有新增截图，滚回后恢复。当前自动化浏览器切换标签仍报告 document visible，因此自然后台页面调度尚未验收，真机资源开销亦未验收。

历史 Windows HTTPS 定向验收中，8 个并发预览请求复用同一拍摄时间和 JPEG，预览不延长 AI 租期；SSE 检查覆盖任务过滤、结束后不接收后续任务事件、重连 resync、caller 拒绝、无效 bearer 不回退、撤销凭证后关闭及退出登录关闭。媒体链路断开与显式新会话恢复另经 Chromium 实际验证，不能用预览结果替代媒体验收。上述设备图像均来自自建端点，没有操作用户手机。

同 caller 的旧任务秘密访问新租约得到 403；任务密钥不同。错误密钥验收由官方 Linux ADB 完成：只加载旧任务 key，实际发送签名；当前任务的不同公钥拒绝该认证，CLI 不输出 ready，连接关闭。没有使用自制 ADB 客户端替代这个认证场景。

同一实际平台的双设备故障窗口中，畸形 OPEN magic 只关闭故障任务；合法格式但错误/迟到的 WRTE stream ID 被丢弃，不派发，也不要求关闭整条连接。另一设备在两个窗口均成功续租、读回自身 serial，并完成独立 stdout/stderr/exit17。慢接收窗口实际扣住一条 29 字节 WRTE（24 字节头、5 字节负载）14.216 秒；期间两端显式续租成功，另一设备命令正常，解除后接收端继续读到数据。此为阻塞隔离证据，不是带宽、延迟或手机编码性能数据。主 agent 最后再次运行两端，核对同一 caller、不同已分配设备和 65539 字节完整 echo，随后明确 disconnect/release 两端并撤销验收 caller。

CLI 对不兼容 API major 2 的受控 HTTPS 响应返回 `API_INCOMPATIBLE` / exit 5，未发出认领请求；写请求正文已接收但响应丢失时返回 `RESULT_UNKNOWN` / exit 6，未自动重发。新连接尚未提交或首次创建得到明确 4xx 拒绝时，清理其未使用的本地连接记录和私有 ADB 目录；随后查询/断开明确报告无连接记录，不伪报创建结果未知。真正响应丢失或已有未确认尝试则保留原幂等身份与 key，不能假报 closed。Windows/Linux 已分别用实际 CLI 和官方 SDK 验证这些分支。

验收中的 WSL NAT 无法直连一个宿主测试端口时，仅使用限定 WSL 源 IP、最多八条连接的临时 TLS 透传 relay，两个地址后端仍是同一 Go 平台；未改 Windows 防火墙，未把 relay 添加为产品依赖。外层 `wsl.exe` 的 localhost 代理/NAT 诊断与原生子进程 stdout/stderr 分开保留，不将启动器文字当作 ADB 输出或吞掉告警。

## 持久资源崩溃恢复与归属隔离

独立临时平台实际启动共享 scrcpy 采集，Chromium 呈现 1920×864 H.264 帧；SQLite 中已有 active ownership 记录和真实推送的私有 JAR。核对可执行文件、数据库及 TCP/UDP 归属后只强制结束该 Go 进程，再以同一数据库和配置启动。新 boot 下旧记录转为 cleaned，进程/helper/JAR 归属探测各执行一次，仅删除本平台 JAR；无关 marker 仍在原路径且为 71 字节。旧网页会话失败，重启后没有自动重连。此场景未创建 AI 租约，不拿它代替此前已有的旧租约重启失效证据。

随后仅在该临时库中注入使用真实 locator 结构但 owner 不匹配的资源记录，公开 recover 返回 `503 RECLAIM_FAILED`，设备保持 quarantined，冲突记录保留 failed，不执行外部清理。主 agent 接手使用证书包含的 localhost DNS 名完整验证 TLS，读取到一条 cleaned、一条 failed；新 caller 认领仍被拒绝且未新增设备服务请求，marker 路径/大小不变。没有删除冲突记录或强行设为 available 来制造成功。

2026-11-09 在 USB 真机上补做强制退出：工作台已解码 1920×1200 H.264 且 capture journal 为 active 时强制结束 Go 平台进程；设备侧 scrcpy 进程随 ADB shell 断开结束，重启平台后旧 journal 转为 cleaned，两台设备均回到 available，无残留 scrcpy 进程或 JAR。真机运行期 scrcpy cleanup helper 可能已提前 unlink JAR，因此清理以 PID/start ticks 和进程环境确认归属，并将 JAR 不存在视为已清理，不要求删除动作再次命中文件。该场景不覆盖平台死亡后仍存活的孤儿进程；孤儿探测仍以协议模拟器注入场景为准。

以上 Android 进程、boot/ticks 和文件来自协议模拟器，不是真机持久进程验证。live 端点无 sync RECV，marker 只验证成功写入和审计路径/大小保留，不声称设备侧字节/hash 对照；普通文件完整性另由官方 SDK 的真实 sync 往返验证。
