# Windows 服务端

`droidharbor.exe` 部署在连接手机的机器。网页和 scrcpy-server 已内嵌到这个单独的 EXE；无需解压服务端包，也无需 Node、Go、源码或单独静态目录。ADB 由外部提供，平台不会启动、替换或关闭系统 ADB。

## 首次使用

1. 将 `droidharbor.exe` 放到当前运行账户可读写的独立目录。
2. 确认外部 ADB Server 已运行，默认使用 `127.0.0.1:5037`；USB 手机直接发现，Wi-Fi 手机也可在网页扫描广播后配对、连接。
3. 双击 `droidharbor.exe`。控制台直接启动，无需脚本或参数；缺少同目录 `.env` 时自动生成完整配置和随机 `DROIDHARBOR_ADMIN_TOKEN`，同时初始化数据库。路径相对 `.env`，不受启动工作目录影响。
4. 首次 `admin_credentials_initialized` 事件向控制台和日志交付初始 `adminToken`，不受普通日志级别过滤；重启不重复输出。令牌明文保存在 `.env`，正常运行日志不回显。保护整个运行目录，分享初始化日志前移除 token。
5. 本机打开 `http://localhost:8080`，局域网打开 `http://服务端IP:8080`，使用 `.env` 中的令牌登录。人工工作台无需安装任务客户端；媒体自动协商地址，无需填写服务器 IP。

网页“添加设备”支持“一键添加所有设备”：使用手机型号命名，已登记链路不再显示，同机 USB/Wi-Fi 经硬件核验归到同一设备。核验保存屏幕尺寸和方向，旧设备上线补采，供工作台及小窗预布局。设备池左侧画面、右侧名称和操作，仅点画面或“预览”进入工作台；离线/未授权设备点“刷新”重新读取并尝试已保存无线地址，手机仍需连接并允许调试，地址变化从新增流程重新扫描。错误统一通知。

“管理”仅编辑名称、标签和 AI 分配；配对地址及临时码只在新增输入，不提供手动加链路或地址修改。新设备默认不可分配，打开管理保留已有设置，人工预览独立。开启分配、空闲关闭直接生效；AI 正在使用时弹窗确认，确认后结束当前任务。弹窗期间任务更换需再次确认，不误停新任务。

无线接入：在“添加设备”点击“扫描局域网无线设备”。已配对手机选择“连接服务 → 连接”，再登记或一键添加；首次配对先在手机打开配对码页面，选择“配对服务 → 输入配对码”，成功后再选择连接服务。两个端口分别使用，配对码提交即清空、不保存或写入普通日志。已登记地址及当前广播可确认的地址别名从待添加清单排除，同机仍通过硬件身份核验归并。

扫描使用现有 ADB Server 的 mDNS，手机需已启用无线调试且该服务器能接收所在局域网的广播；不扫描全部 IP 或端口，不增加 `.env` 配置。未广播设备保留手动地址入口，ADB/mDNS 故障会明确通知并记录 requestId，而不是显示成没有设备；不为此改动 TLS、域名或系统网络设置。

应用使用 HTTP，不配置证书、私钥或固定 origin。令牌、会话和 CSRF 校验保持生效。桌面 Chrome/Edge 是本轮目标；聚焦手机画面后直接 Ctrl+V，使用浏览器粘贴事件，无需 HTTPS 系统剪贴板 API。剪贴板历史按设备保存在当前登录页面内存中，最多 20 条；刷新或退出清空，不自动写入电脑系统剪贴板。

## .env 配置

首次生成的 `.env` 包含全部常用项；登录令牌始终以该文件为准，其他配置可由同名进程环境变量覆盖，便于服务/容器部署。支持引号、注释、Windows CRLF 和 UTF-8 BOM。

| 项目 | 配置名 | 默认/说明 |
| --- | --- | --- |
| 网页/API | `DROIDHARBOR_LISTEN` | `0.0.0.0:8080` |
| 媒体 UDP | `DROIDHARBOR_RTC_LISTEN` | `0.0.0.0:8081` |
| 媒体地址覆盖 | `DROIDHARBOR_RTC_ADVERTISED_IP` | 可选，默认自动协商；特殊网络才指定 IPv4 |
| 外部 ADB | `DROIDHARBOR_ADB_SERVER` | `127.0.0.1:5037` |
| 数据库 | `DROIDHARBOR_DATABASE` | `data/droidharbor.db` |
| 登录令牌 | `DROIDHARBOR_ADMIN_TOKEN` | 首次自动随机生成，明文保存在 `.env` |
| 上传暂存 | `DROIDHARBOR_TRANSFER_TEMP_DIR` | `data/transfers` |
| 运行日志 | `DROIDHARBOR_LOG_FILE` | `logs/platform.jsonl` |
| 日志级别 | `DROIDHARBOR_LOG_LEVEL` | `info`，排障可改 `debug` |

高级可选项：`DROIDHARBOR_ADMIN_SESSION_TTL`（`12h`）、`DROIDHARBOR_ADB_TIMEOUT`（`10s`）、`DROIDHARBOR_TRANSFER_MAX_UPLOAD_BYTES`（268435456）、`DROIDHARBOR_TRANSFER_MAX_ACTIVE`（8）、`DROIDHARBOR_TRANSFER_MAX_COMMAND_OUTPUT`（65536）。明确覆盖内嵌资源时才设置 `DROIDHARBOR_WEB_DIR`、`DROIDHARBOR_SCRCPY_SERVER`。

## 停止、升级与排障

- 保持控制台窗口运行；Ctrl+C 停止。启动失败非零退出；从资源管理器双击启动时保留错误窗口，已有 CMD/PowerShell 或服务不等待输入。缺配置自动生成；已有配置格式、类型或必需令牌无效时明确失败，不覆盖修复。
- 升级前停止并备份 `.env` 与 `data`，再替换 EXE 并刷新已有网页。schema 1 自动原地升级到 2，保留设备身份、名称、标签、维护和画质配置；回退旧程序时恢复匹配的旧版备份，不用旧程序直接打开已升级库。交付 EXE 不附带运行配置、凭证或数据库。
- 日志同时输出到控制台和 `DROIDHARBOR_LOG_FILE`；每文件 20 MiB，最多保留 5 份压缩历史。文件创建失败直接退出，运行中写日志失败直接报告 stderr。
- 用发生时间、requestId、关联设备/会话查故障。首次管理员初始化事件包含 token；其余事件不记录凭证、配对码、完整 shell 命令、剪贴板或设备原始输出。日志目录按凭证资料保护。
- 采集异常日志的原因链包含启动/回收阶段和内部固定错误原因。设备异常时从设备池点“刷新”，重新核验和恢复平台自有资源；不清手机应用或停止外部 scrcpy。
- 离线、未授权和待核验设备均有“刷新”。先连接手机并处理授权；无线刷新尝试已保存地址，不重新配对、改变分配设置或复活旧 AI 任务。地址变化从新增流程重新扫描。
- 启动、接入及重新上线立即恢复已登记设备、读取主屏尺寸、获取一张共享封面和首批指标。单台尺寸失败仍保留已核验在线状态、已知尺寸和错误；刷新可重新读取，不需要清空 data。同一手机尺寸读取跨 USB/Wi-Fi 互斥，不同手机独立。
- 已登记手机在线期间自动逻辑唤醒、实体黑屏，关闭所有网页也保持；空闲只运行共享无音视频控制，不持续编码。最后视频回收不结束保活，断开/移除/停平台后结束并按原策略自然休眠，不改手机休眠时限或解除既有密码锁。标准 scrcpy 恢复休眠时可能短暂亮屏；工具栏“点亮实体屏幕”是显式实体电源操作。
- 设备池及工作台卡片每五秒更新整机 CPU、已用/总内存、电池温度、电量及实际充电状态；label/value 同行。CPU 首次显示采样中，接电不等于充电，读取失败分项显示不可用并统一通知；指标不保存历史，不改变分配状态或编辑草稿。
- 轮换登录令牌：停止平台，修改 `.env` 的 `DROIDHARBOR_ADMIN_TOKEN` 后重启。启动撤销其他凭证版本的旧登录会话，改回旧令牌也不会复活已撤销会话；不需要独立初始化命令或脚本。
- 本包不安装 Windows Service，不配置系统网络。服务部署可用 `serve --env-file 配置文件绝对路径`，运行参数仍由该文件读取。
- 新登记设备默认上限 60 fps、目标 12 Mbps；下拉支持 30/60/90/120 fps 与 4/8/12/20/40 Mbps。长边仍为后端策略，默认 1920；已有设备配置不自动改写。
- 工作台设备卡片左侧完整预览、右侧基本指标，底部分辨率/fps/当前窗口视频状态固定同行；缺失数据保留占位，连接前后和离线不改变卡片高度。侧栏默认 320 px，可拖到 280–440 px；未选中设备也显示已知尺寸，fps 不冒充其他窗口状态。
- 设备池和工作台预览按真实比例缩放至可用宽度及最多 180 px 高度，容器不补黑边、不裁切或拉伸画面；手机画面自身的黑色照常保留。当前小图最多每秒四次取自本页视频，切走冻结最新帧、后台不刷新，工作台不轮询截图。设备池仍每五秒共享截图，新图解码后替换，失败保留同链路旧图并统一通知。
- 设备池不同设备的截图/JPEG 处理直接并行，没有固定采集并发数或全局排队；同设备请求仍共享结果。保留五秒刷新间隔、单次十秒预算及图片/缓存/链路状态边界，真实超时和设备故障仍明确通知，不隐藏错误或降低画质。
- 画质和剪贴板常驻右侧；操作栏贴着矩形手机画面，返回、Home、最近任务固定在底部，其余操作置顶，高度不足时上部可滚动。背景随主题。主界面和小窗使用已保存的真实比例预布局，首帧同尺寸时不再跳变；小窗按高度算宽、解码前校准浏览器边框，保留三档尺寸与手动缩放。
- 正常切换后，每个已访问设备独立保留完整视频链十五秒，包括 WebRTC、媒体轨道、video 节点及解码器；切到第三台不会淘汰前两台。期限内回切直接显示原视频并取消该设备倒计时，下次离开重新计满十五秒。切走立即释放输入并取消旧操作作用域，回切核验权限并确认当前实际帧后开放控制。全部保留窗口计入既有 64 个媒体会话容量，期间继续编码和传输；不预热未访问手机。超时只回收对应窗口；普通关闭、退出、过期、断连、失败或停服务回收，不修改 AI 租约。
- 当前工作台及独立小窗遇到瞬时视频故障按 1/2/4/8/15 秒自动恢复，稳定十秒重置；离线等待重新核验在线，切走或关闭取消。健康后台流仍独立保留十五秒，失败后台项不主动重建。保持原模式、画质和 AI 租约，实际新帧确认前禁用输入，旧操作不重放。
- 同设备回收进行中等待实际结果；登录失效、协议/编码不兼容及回收未确认停止恢复并统一通知，不绕过隔离。`media_recovery_attempt`、`media_recovery_session_prepared` 与同 sessionId 的 `media_frame_presented` 区分尝试、准备和真正出画面。
- 观看队列仍限制八帧/4 MiB，瞬时满时丢弃整段旧视频并在原连接等待新关键帧，不降画质；重复关键帧请求合并。首次积压后五秒内未能完整发送恢复关键帧，或单帧超过字节上限，才以 `SLOW_VIEWER` 结束。必要 RESET_VIDEO 会更新同设备共享采集的画面代次，不等于关闭其他窗口连接。
- `media_viewer_backpressure` 记录 reason、queuedFrames/queuedBytes、frameBytes/framePackets、lastFrameSendMs/inFlightFrameMs；`media_viewer_backpressure_recovered` 表示完整关键帧恢复发送，真正呈现仍看 `media_frame_presented`。仅凭 SLOW_VIEWER 不判断手机或网络故障。
- 设备预览因浏览器切页或关闭而取消时记录 `preview_request_canceled`/499，不误报截图失败，也不取消其他查看者共享的采集；实际设备采集失败和超时继续明确记录。
- “手机横竖屏切换”是物理旋转请求，能否生效由应用及系统策略决定，不代表向右旋转九十度；方向未变通过全局通知提示。“网页左转”和“网页右转”分别旋转网页画面九十度，只读也能使用，不改变手机方向。日志 `scrcpy_device_rotation_requested` 仅表示设备收到请求，不是实际方向确认。
- 同版本采集程序在手机端校验后缓存，运行使用独立路径并定向清理；版本缓存不是活跃采集进程。日志 `capture_artifact_uploaded/reused` 区分准备与复用，保留/恢复/开始回收/完成回收各有事件，缓存异常保留阶段与退出码。
- 建连不等待浏览器收集全部网络候选；信令准备、RTC 就绪、帧边界发送及实际呈现有独立耗时日志。首次进入、保留期已过或采集失败仍需要冷启动，不用旧预览冒充新视频。

## 重建与客户端

项目根目录执行 `npm run package:windows`，需要开发工具链和锁定 scrcpy-server。输出 `release/windows-amd64-时间戳` 下仅两个交付文件：`droidharbor.exe` 和 `DroidHarbor-skill.zip`；已有输出根目录拒绝覆盖。任务调用机安装 ZIP 内完整的 `droidharbor` Skill 目录，其中 `SKILL.md` 与 `scripts` 一起保留，按系统选择内置 Windows/Linux amd64 CLI 的绝对路径；Linux 首次赋予执行权限。完整使用流程见 [产品 Skill](../../skills/droidharbor/SKILL.md)，无需独立 CLI 包或全局 PATH。人工浏览器操作不需要客户端 Skill。
