# Proposal

## Why

现有方案不能满足按账号环境分配真机、任务级原生 ADB 授权和可维护的网页控制需求，用户已决定独立重写。DroidHarbor 首版要为约 3–10 台 Android 手机建立完整的“领用—连接—操作—显式续租—释放”闭环，并提供统一网页人工入口，而不是只交付投屏界面或后端骨架。

## What Changes

- 新增 USB/Wi-Fi ADB 设备登记、授权/配对、稳定设备身份、双链路去重、标签匹配和维护状态。
- 新增任务级原子认领；认领及每次显式续租有效 15 分钟，不限制续租次数或累计任务时长。到期、撤销及平台重启使旧授权失效。
- 新增服务端强制执行的租约 ADB 网关，覆盖已建立 transport、shell/sync 子流、待派发数据和重连；不开放原始服务端 ADB 管理端口。
- 交付 Windows/Linux Go CLI 及产品操作 Skill。每任务独立本地 ADB 实例、配置和入口，不依赖 harness 插件，不自动续租、换设备或重放操作。
- 新增桌面网页设备池、管理与工作台：左侧全局导航、可拖宽的大预览设备列表、紧贴手机的竖排操作栏；AI 占用用图标表示，观看不改变 AI 租约。提供 scrcpy 式鼠标/键盘、多指、中文粘贴、剪贴板历史、截图及只读会话；右侧常驻画质和历史，不提供文件操作入口、独立文本表单或全屏按钮。
- 设备池可见设备默认每五秒共享截图；工作台仅从当前视频取帧，切走前保留最新一帧，未选中设备冻结且不发起截图刷新。刷新保留已有图像至新图解码完成，不回退到观看前的旧截图；保留真实新鲜度资料，侧栏不显示时间文案，离线置底置灰。
- 独立浏览器 popup 保留独立生命周期和必要操作；首次按可用高度及手机比例计算宽度，允许移动/缩放并反馈浏览器限制。主工作台和小窗使用主题背景，视频保持矩形且完整等比显示。
- 手机 H.264 编码、Pion WebRTC 转发、浏览器解码；每设备共享采集。新登记默认 60 fps、12 Mbps，网页使用 30/60/90/120 fps 和 4/8/12/20/40 Mbps 下拉档位；后台保留分辨率策略，不在网页展示长边控制。
- 回收仅撤销访问并清理平台拥有的资源，保留手机应用、账号、业务文件及后台状态；清理失败隔离，连接健康且清理完成后回池，不保证设备副作用清零。
- 提供 Windows 原生和 Linux Docker Compose 双容器部署；后者分别运行平台与 ADB。SQLite 持久化业务元数据，内网/VPN 使用；浏览器范围为桌面 Chrome/Edge，不考虑移动端。
- 提供管理员访问令牌登录、可撤销调用凭证、能力发现、版本合同、状态事件、运行记录及备份恢复；静态前端、API、网关与投屏由单 Go 服务统一提供。性能先测量，再由用户确认数值验收门槛。
- Windows 服务端和客户端独立打包。服务端 EXE 内嵌网页与 scrcpy-server，双击直接打开控制台；无 `.env` 时生成可用配置与随机明文 token，`.env` 为管理凭证唯一来源，无示例、启动脚本或摘要文件迁移。保留自动初始化、轮转日志、故障诊断及 WebRTC 自动地址协商；应用提供 HTTP/WS，不承担 TLS、证书或域名。
- 设备接入核验时保存显示尺寸及方向，旧设备自动补采；工作台及小窗使用持久化显示信息预布局。优化固定布局、同版本采集程序复用、并行建流与首帧获取；正常切走保留最近候补窗口的采集、WebRTC 连接、MediaStream、video 节点与解码器十五秒，回切直接复用完整视频链。后台立即释放输入并撤销操作作用域；退出、撤权、断连及停服务回收，AI 租约保持不变。
- 选中设备自动逻辑唤醒并进入标准 scrcpy 息屏投屏，实体屏正常投屏阶段保持黑屏；采集期间 keep-active，不改系统休眠时限。用户接受系统休眠恢复可能短暂亮屏，不做高成本零闪亮定制；最后一份采集退出采用上游熄屏清理，不自动恢复实体亮屏，AI 租约与输入权限保持独立。

**明确不做**：音频、录屏、群控、应用仓库、MCP、多语言 SDK、完整权限管理后台、SSO、多宿主调度、集群高可用、公网直连、eScrcpy 入口及共存兼容、Document PiP 或小窗强制置顶。Appium/uiautomator2 只保留连接、能力及生命周期扩展合同，不部署、不实现、不宣称兼容。

本变更是首版整体交付的规划单元，内部按可运行纵向阶段实施，不能把阶段性骨架当作首版完成。已有设备登记和运行数据使用版本化迁移保留，不兼容参考项目接口或数据。

## Capabilities

### New Capabilities

- `device-pool`：设备登记、USB/Wi-Fi 接入、稳定身份、标签、连接状态与分配资格。
- `task-leases`：原子认领、任务授权、固定租期、显式续租、撤销、回收与重启失效。
- `remote-adb`：原生 ADB 连接、服务协商、二进制桥接、子流撤销及未来工具边界。
- `caller-skill`：harness 无关的 Skill/CLI 使用流程、本地任务环境、错误与退出清理。
- `web-workbench`：网页人工控制、设备切换及首帧优化、显示信息预布局、独立小页面、共享低频预览、只读权限、媒体共享、可调画质与截图。
- `access-control`：管理员及调用方认证、凭证撤销、任务凭证隔离和数据可见范围。
- `platform-operations`：双部署、持久化、服务恢复、版本发布、健康检查、备份和测量交付。

### Modified Capabilities

无。当前 `openspec/specs/` 尚无正式能力规格，以上均为新增能力。

## Impact

- 依据：[项目规划](../../../docs/项目规划.md)、[原始需求](../../../ref/需求&选型.md)及本变更的设计、规格与任务清单。
- 实现保留既有设备、标签及授权资料；2026-11-11 用户选择 B 档并批准新增设备显示信息的数据库迁移。
- 实现涉及 Go 服务与 CLI、React/TypeScript 前端、SQLite schema/迁移、API 合同、设备协议适配、产品 Skill、Windows 服务配置、Linux 镜像/Compose 及验收文档。
- 用户已批准工程实施及 `design.md` 第 9 节数据库 schema；后续架构或 schema 调整仍须确认。
- 依赖官方 platform-tools、锁定版本的 scrcpy-server、Pion 和 frontend-library 指定组件；具体版本及兼容矩阵以获取和运行证据为准。
- UI 延续已批准桌面布局；仅操作指定设备，不以规划、编译或模拟数据代替产品验收。
